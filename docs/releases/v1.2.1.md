# v1.2.1：取消自动评价邀请、主备接口池与中文管理

本版保留 Crisp、n8n、AnythingLLM、PostgreSQL 与原有客服控制规则。下文说明代码能力和安装流程；TARGET-A 同包、正式发布及匿名核验结果由同 Release 的独立 `v1.2.1-verification.md` 回执证明，未取得相应回执不能把本页当作验收完成证据。

## 主要变化

- 不再自动追加评价文案、评分链接或评价按钮；新装、升级、重复初始化与旧业务导入均停用邀请。旧待评价状态不消费新的“是/否/👍/👎”，历史统计保留只读，人工 offer 和普通待处理任务不清空。
- 发送者使用中性“在线客服”，不额外添加“机器人/AI 回复”后缀，不请求可选 automated 徽标；发送前持久登记自有 fingerprint，兼容旧回流且不依赖昵称猜真人。平台实际显示由 TARGET-A 同包 SDK 验收证明，不能以代码字段推断标签已消失；直接被问身份时如实说明自动客服。
- 主菜单 3 管理 1 主、最多 20 备，总计 21 项，停用和草稿也占名额。十项初始化只填主接口，没有备用合法。旧地址、Key、模型、协议和自定义头迁移为主接口，不重问多套凭据。
- 非秘密池源、原子有效投影和受限秘密代次分离；只有 adapter 挂载全池上游秘密，n8n/AnythingLLM 使用独立内部认证。旧 `.env` 单接口字段只是兼容投影。
- 按配置顺序处理可恢复接口故障，文本与图片两阶段共享问题预算：默认 90 秒、最多 21 次，单次 20 秒、连接 5 秒；不为安全拒绝或明确输入错误切换，也不修改 workspace、重建索引或转人工。
- 普通菜单用中文摘要显示真实业务状态，关闭欢迎不再混用总开关回显；18 主菜单、数字返回/取消和显式结构化脚本接口保留。
- 诊断导出区分已知模型 token 数量与真实秘密，避免数值偶合导致误拒绝；真实数字 Key、多接口秘密及编码仍严格过滤和二次检查。
- 人工接管兼容官方省略 automated 的操作者消息，仍以可信事件及身份核对处理，网站级 API 消息和内部备注不冒充真人。
- 真人公开回复立即暂停对应会话并作废未发送结果；新装及缺省恢复时间为 3600 秒，可从菜单 7 修改。系统异常出口不再发送机械的稍后重试话术，改为简短的相关澄清，不改变维护诊断的真实失败状态。
- 修复身份资料不完整的 operator 回流与紧随其后的访客消息竞态：访客任务在身份确认前持久延后，确认非真人后自动继续，确认真人后才按会话取消；无法确认时仍保留控制事件之后的新问题。归属结果与代次栅栏同事务持久化，多个未决事件、同时间戳、runtime 重启及事务间崩溃均保持顺序与单次出站。
- 人工控制优先于普通队列容量；满控制队列时仍先暂停，不因非关键标签无法排队而回滚接管。合法按钮的确认有唯一有界优先位置，旧任务和未知发送对账保留。
- 接口的上下文预算实际投影到 AnythingLLM；聚合值变化时受管重建并回读，失败成套恢复。最终请求检查当前完整 Prompt，拒绝把预处理已截断的内容发送给上游。
- 识图阶段先提取当前图片的可见事实，历史只作引用背景，再交给原有知识问答；修复实机上将前一文字题答案误存为图片摘要的路径。原 Prompt、会话隔离、共享预算和人工取消保护保持。
- 修复中文知识完整 FAQ 未被送入模型的高优先级问题：检索只使用当前问题，完整 FAQ 原问由受管词法索引稳定补回，普通改写继续与真实向量结果合并；“问/答”“问题/答案”“问题/回答”均生成明确问句字段。菜单 5 的问答测试与客服共用生产核心，始终使用全部已启用库；停用库不能进入新来源。有界补召回最多 4 条、合计 2 MiB；资源足够时安全迁移到多语言 Embedding 和 400 字符块。问答热路拒绝 materials/map/lexical/profile/settings 代次不一致的资料；manifest/cache 完整性由同步、profile 维护链和 doctor 核对。
- 重复安装会在修改运行树属主前完整校验知识控制投影，并以新 inode 恢复受管权限；旧业务恢复也会在停服和资料覆盖前核对当前 profile、manifest、迁移状态与向量缓存绑定，拒绝用损坏代次生成新的“已应用”状态。
- 修复在线快照预检将正常消失的短命锁误报为异常文件的问题；权限、链接和真实读取错误仍阻止备份，停止写入后的正式复制不降低一致性要求。
- `crispai apply --check` 先校验业务和池源；明确 `crispai apply` 才应用。业务已成功但池失败时分别报告，保留业务新值和上一有效池，不假称整体成功。

主备切换可能把必要 Prompt、知识、同会话公开历史或图片发送给另一个可信服务，并增加费用；添加前确认授权与余额。没有后台持续付费轮询。默认冷却 60～300 秒，不截短更长的上游 `Retry-After`；完整限制见[配置说明](https://github.com/statusX7/ai-support/blob/main/docs/CONFIG.md)。

## 已安装实例与迁移

正式发布后用 `crispai → 14 → 1` 更新；升级前一致快照，失败按实际恢复结果处理。受管 `crisp` 兼容入口继续与 `crispai` 共用管理器，入口单独损坏仍用同版本 `get.sh --repair` 的窄救援流程。

欢迎、总开关、已有人工恢复 1800/0 或其他合法自定义值、Prompt、知识和会话控制保持；新装及缺省人工恢复为 3600 秒。自动评价邀请是本版明确停用项。业务包不带上游 Key/请求头值：未知主接口先存草稿而不替换当前池，缺 Key 的新备用保持停用，补齐验证后显式应用。完整本机快照则包含恢复所需秘密与状态，不能公开。

第三方接口地址在向导、菜单、有效池和运行 adapter 采用同一规范：例如供应商给出的 `/api` 会形成 `/api/v1`，已有 `/api/v1` 保持不变，再分别调用 `/models`、`/chat/completions` 或 `/responses`。保存不再只凭模型列表或 revision：候选须完成实际协议验证，运行 adapter 还要回读应用状态、同代接口 ID、顺序与启停；失败成套恢复旧配置。普通界面按鉴权、模型/端点、协议、响应结构、限流、额度、超时、上游或容器网络给出中文原因。

已有接口池再次运行快速初始化时，不再让旧池覆盖刚输入的新主接口：程序保留原主稳定 ID 和全部备用顺序，以同一个候选事务验证并更新地址、Key、模型与协议。Responses 探针允许推理型模型先产生少量 reasoning 后返回可验证正文；实际推理端点的普通 404 会作为地址/协议不兼容尝试备用，模型列表端点 404 则保留手填模型路径，明确模型不存在仍不会误伤同接口的其他模型。

未完成十项初始化再次进入时，可数字选择继续上次、重新开始或取消；重来只清理严格属于该向导的临时草稿。受管 Caddy 在首次启动、Crisp 设置修改、服务重启和恢复时统一做候选语法验证、容器内文件摘要回读及 last-good 恢复；由受管 HTTPS 切到外部反代只删除本实例 Caddy，不触碰其他站点。恢复旧反代不表示新候选成功，本次操作仍准确失败。

真人公开回复现在也会中止已经进入 Crisp HTTP 发送阶段、但尚未取得确定回执的普通自动出站；跨运行实例以持久会话代次和逐尝试令牌作废迟到结果，另一会话不受影响。调度扫描锁改用进程身份、启动代次和心跳，旧空锁仅在 n8n 停写维护窗口迁移。快照与回滚已把 adapter、router、Provider/配置脚本纳入同代校验，避免升级恢复后运行旧推理代码。

## 验收与发布状态

验收采用固定顺序：冻结完整包 → 本地真实组件与授权 TARGET-A 同包验收通过 → push/tag/draft/Release → 匿名回下载、空机安装与目标机正式同包核验。任何生产差异都须重新核对完整候选；真实是否通过、失败边界及正式资产身份以独立回执为准，不由这份能力说明替代。

本轮 F8+A28+U12+R14 合计 62 个验收场景，场景清单不等于已通过数；协议 fixture 不等于真实多家账号，构造的 `automated:false` 不等于后台真人操作。最终结果、原始失败与外部边界由该版报告和独立 `v1.2.1-verification.md` 回执逐项记录，不引用 v1.2.0 历史成功填充本轮结果。
