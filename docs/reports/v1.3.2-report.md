# v1.3.2 修复报告

## 根因与修改

本轮现场是重新安装的 Ubuntu 24.04，原部署 v1.3.1 处于 installing。真实日志证明完整 Prompt 基础输入估算 47311、含输出至少需 48511，而主接口窗口只有 8192；五个组件运行不代表客服可用。容量保护正确，错误是恢复入口无法编辑及应用配置。

| 问题 | 根因 | 修改 |
| --- | --- | --- |
| 重跑不能编辑 | 完整 .env 被直接复用，未进入已有向导选择 | 可保留、修改、取消；现有数据回填，取消不改正式状态 |
| 大 Prompt 无法配置 | 向导未收集窗口，原主接口更新未携带窗口 | 可手动修改窗口；接口池、兼容环境、RAG 预算成套应用回读 |
| 重配遗留事务 | 安装先标 installing，而 RAG 应用只允许 ready/local-ready | 接受安装中实际受管组件，保留归属/鉴权/回读；未启动时先准备，事务沿原恢复方法收口 |
| 原域名冲突 | 本实例 Caddy 的 80/443 被视作外部占用 | 必须核实运行配置、实例归属后才允许复用 |
| 无 crispai | 入口创建位于最终健康门禁之后；菜单也拒绝未完成实例 | 安全创建条件满足后先建入口，允许续装/接口修复，仍保留失败和非 ready 状态 |
| 无法接手旧安装 | 在线入口强制锁定失败的旧版 | 显式选择较新正式修复版；完整安装器只允许较新版接手未完成实例，正常升级流程不变 |

保留内部 API Key、模型稳定 ID、Prompt、知识及原有人工/出站责任，不删除失败任务或强行重放；65535 仅是用户确认的当前中转设置，不是所有模型的默认能力。项目持续维护，版本政策随明确授权更新，历史发布不重写。

## 已完成源码阶段证据

TARGET 上执行原模块和真实状态文件：17 组向导、11 组原安装恢复、6 组新增安装恢复、33 组在线入口、3 组未完成状态管理菜单通过。新增恢复覆盖取消保留、窗口输入、完整配置应用及真正失败事务的原入口恢复。外部服务在这些契约测试中为明确替身，不是实机部署验收。

真实现场执行“编辑原域名后取消”：1.674 秒退出取消，正式 .env、安装标记、Provider 配置、Prompt/知识和 Caddy 全部未变，原受限草稿恢复。保留开发期间失败记录：实际 RAG 状态互锁与随后 Docker 替身缺少合同、辅助函数误名分开记录；没有改预期掩盖产品错误。安装回归累计826.400秒，之后不重复整批。

## 冻结后的必要验收

完整候选仍须实际安装到测试目标，检查运行代码、窗口回读、服务、自检、原咨询责任及真实业务；干净 VM 要覆盖长 Prompt 在8192下失败、管理入口可用、修改65535后续装成功，并销毁自有虚拟机和磁盘。冻结包不能包含之后才获得的结果；最终提交、归档摘要、实机及匿名分发事实写入同一 Release 独立核验附件。关键项不通过则不发布。

全面审查以18类既有功能和当前改动调用链为范围导航；未变化的模型协议、消息/人工/知识/备份等复用同源码有效证据，不宣称全量重测或零 Bug。没有重建 Haruka 项目、没有增加 Guard/框架或子 Agent；按用户指定 Stop That Shit 准则复用现有向导、事务和发布工具，仅补实际缺口。
