## 1. 基线与版本政策

- 公开基线：v1.2.1，tag commit `4b923d60233f48a37d545d3f345200cfa8161266`；远端 Latest 在本轮开始时仍为 v1.2.1。
- 开发起点：`4139e4b69440c33cef8e3fb088426253addb0f07`，工作树包含未提交的 v1.2.2 开发素材。
- 本轮唯一目标：v1.3.0。`config/release-policy.json` 明确禁止自动递增、只允许一个 v1.3.0 新 Release，并要求 TARGET-A 同包验收。
- 发布入口、打包入口和源码门禁均校验该政策；正式结果尚未发生，不在本报告预填。

## 2. v1.2.2 时间线复盘

已核对的事实：v1.2.1 于 2026-09-14 正式发布；之后本地未提交工作树把 VERSION 与 AGENTS 目标改为 v1.2.2，并记录了干净安装 Compose 候选校验、runner 饱和、REST 补偿等技术修复。Git 中没有 v1.2.2 commit/tag，GitHub 没有 v1.2.2 Release。当前可见记录未找到用户授权切换产品版本的证据。

因此，技术上继续修复公开包新发现的缺陷具有明确动机，但“发现缺陷”不等于“获准创建新产品版本”。本轮将未提交实现作为待审查素材纳入 v1.3.0，而不是发布或改写历史。

## 4. 当前已落实的修复与现场结果

- 漏答责任：已修复未知身份控制任务异常不进入既有退避记账的问题。用户确认的过期控制窗口规则按可信事件时间生效，保留历史、身份仍为未知，不继续阻塞窗口后的新咨询；相邻历史真人控制亦按实际适用窗口判断。永久人工、有效接管、总开关和去重保护保留，不恢复全部取消任务。原被阻塞咨询已自然完成，实际模型成功且官方精确确认仅一条答复；该答复属于必要的具体澄清，不宣称客户故障已解决。
- 知识和菜单：当前链路已实际加载已验证菜单选择的用户事实、已确认的菜单展示历史及咨询方向，修复菜单与普通问答的相关上下文缺口。用户确认的两条精确短词业务意图使用现有关键词 prompt 功能承载；原规则保留，没有新增固定业务答案或另一套路由器，两条当前真实客服答复分别给出对应步骤并唯一送达。
- 接口适配与主备：已实际验证候选添加、备用升主、显示与真实顺序一致，以及用户指定备用和 DeepSeek 的实际客服调用。连接及认证失败、全池失败保留责任和原任务自然恢复、冷却与重启恢复已有分项证据；这些不等同于任意供应商或全部故障矩阵通过。
- 图片：一次当前真实业务图经过识图、摘要持久化及最终回答。主识图成功，主回答阶段 HTTP 200 的无效响应未被伪报成功，真实路由随后选择备用成功；三个实际尝试共享同题预算，最终仅一条业务答复。精确临时来源配置经用户许可加入并恢复，原环境及其它服务保持；本结果不代替原生上传 API 或浏览器验收。
- 本轮最近一次普通只读自检（本次受管资料更新前）为 70 通过、1 关注、0 故障、4 未执行；退出码 2 保留。关注项为 Caddy 没有 Docker healthcheck；未执行的是显式外部检查，不能据此称完整上线通过。没有为消除诊断结果而删除失败责任或放宽业务保护。
