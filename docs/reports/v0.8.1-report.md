## 5. 修改内容与新增功能

- `uninstall.sh` 默认执行安全卸载，`--keep-data` 作为兼容别名；安全卸载前始终在 `backups/` 中创建唯一的不含密钥迁移备份。
- Docker 资源成功删除后，安全卸载会删除 Compose 定义、根级程序文件、脚本、workflow 副本、程序文档和临时目录。
- 安全卸载保留 `config/`、`knowledge/`、`data/`、`backups/`、`logs/` 及权限为 `0600` 的 `.env`，并将安装状态写为 `uninstalled-data-kept`。`.env` 必须保留，否则 PostgreSQL 密码和 n8n 加密数据无法复用。
- 安全卸载后可从新的可信源码目录对原路径重新执行 `install.sh`，保留数据和密钥会被复用。
- `--purge` 必须先输入 `y` 或 `yes`，再精确输入 `PURGE`；即使指定 `--yes` 也不能绕过两次确认。
- 完整清理前始终将不含密钥的迁移备份写到部署目录同级，再删除整个部署目录。该备份不含 `.env`、数据库或 AnythingLLM 运行数据。
- Docker CLI、Compose、daemon 或 `docker compose down` 不可用时，脚本在任何程序或数据删除前返回非零；不再提供强制离线绕过。
- 卸载完成会分别显示删除内容、保留内容和恢复方式。
- `manage.sh` 主菜单收敛为指定的 11 项：查看状态、修改 AI 配置、管理 Prompt、管理知识库、查看统计、查看日志、备份、恢复、更新、回滚、卸载系统。
- 历史版本合并到状态子菜单，知识库命中与 AI 回答质量合并到统计子菜单，安全卸载与完整清理通过卸载子菜单选择。
- 新增管理菜单映射契约测试，并扩展卸载、失败原子性和同路径恢复回归。
- 保留 v0.8.0 已有的 Crisp webhook、n8n、AnythingLLM、Provider 检测、图片、上下文、欢迎、菜单、关键词、人工接管、标签、统计、备份、更新和回滚逻辑，未扩展多客服、权限、坐席或 CRM 范围。

## 7. 安装方式

正式验收环境的预期入口为：

```bash
git clone https://github.com/statusX7/ai-support.git
cd ai-support
sudo ./install.sh
```

安装脚本会检查 Docker Engine 与 Compose v2，创建受管目录，生成或复用密钥配置，检测 OpenAI Compatible Provider，启动服务，引导 AnythingLLM，发布 n8n workflow，并在完整健康检查通过后将安装状态设为 `ready`。当前本地候选版尚未 push，因此该 `git clone` 命令只是正式发布后的部署方式，不是当前可验证的发布地址。
