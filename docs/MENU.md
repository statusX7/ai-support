# CrispAI 中文管理菜单

安装完成后，在任意目录执行 `crispai`；普通用户可执行 `sudo crispai`。不必进入源码目录，不需要 alias 或重新登录。`crispai --help`、`crispai --version` 不访问外部 API。也支持 `status`、`doctor`、`init`、`apply`、`logs`、`enable`、`disable`、`uninstall`。兼容命令 `crisp` 仅在没有其他程序占用时登记，复用同一入口；正式命令仍为 `crispai`。

首次使用从 [公开仓库新手安装教程](INSTALL.md) 开始，无需 GitHub 登录或下载 Token。下面的 `3 → 10` 表示主菜单 3 后再选子菜单 10，不是要在 Shell 中执行的命令。

宽度至少 80 列的 UTF-8 交互终端显示 Emoji 双栏；窄屏、`TERM=dumb` 或非交互输出降为单栏。`CRISPAI_NO_EMOJI=1 crispai` 使用纯文字。主菜单读取本地事实，不自动发付费模型请求。显示“待验证”不代表已连接客户。

## 操作约定

所有子菜单 `0` 返回；非法数字重新提示。空输入按提示保留或取消，不表示同意危险操作。EOF 退出；Ctrl+C 中断未确认输入，已生效配置保留。需要确认时只输入数字 `1` 或 `0`。程序明确提示失败或待生效时，不要把文件已经写入理解为运行成功。

多行正文：逐行粘贴，单独一行 `::END::` 保存，`::CANCEL::` 放弃；正文需要这两个字面量时写 `\::END::` 或 `\::CANCEL::`。中文、空行、Emoji、引号、反斜线、`$` 是数据，不会作为命令执行。空正文不覆盖旧 Prompt。

受管目录下的 `config` 与 `knowledge` 保存权威业务原文，秘密由受限 `.env` 和接口秘密代次文件管理；候选先校验再保存、应用与回读。`config/materials-applied.json` 与 `config/provider-pool-applied.json` 是程序管理的有效投影，不要手改。普通界面用中文解释实际结果，不显示机器对象或内部编号；文件写入不等于已生效。直接编辑原文后运行 `crispai apply --check` 检查，再用 `crispai apply` 或 `16 → 6` 应用。不要直接修改 AnythingLLM/n8n Web UI，否则可能与受管资料偏离。需要机器回执时，`apply`、`enable`、`disable`、`status`、`doctor`、`logs` 支持显式 `--json`；参数放在命令后，stdout 只输出结构化结果，失败退出码仍保留。

## 1. 快速初始化

未安装直接进入十项向导；已安装显示 `1 保留现有配置继续检查与修复 / 2 重新运行十项初始化（保留数据）/ 0 返回`。默认不会清空知识或重生密钥。普通文件路径流程为十项主要输入，确认后零次内部参数必答；粘贴及多库编辑是相应步骤内的自选输入。[安装手册](INSTALL.md)列出全部步骤。

若向导仍处于 `collecting`，再次进入会显示记录的下一步骤，并提供 `1 继续上次 / 2 重新开始 / 0 取消`。继续只从该步骤往后收集；重新开始只删除经过文件类型、所有者、权限、链接数、文件名和受管工作目录共同确认的本向导临时知识草稿，再重置十项收集状态。无法确认归属的文件保留供检查；已部署 `.env`、业务配置、Prompt、正式知识库、密钥和会话数据都不属于该清理范围。

新装默认：客服启用、人工关键词确认按钮启用、恢复 3600 秒、欢迎启用、自动展开关闭。升级保留已有合法设置。示例：中断后运行 `crispai init` 续装，不重新创建数据库。安装可能拉镜像、启动服务和下载本地 Embedding；外部凭据错误只修对应项。

## 2. 状态与自检

子菜单：`1 快速自检：本地组件与配置状态 / 2 完整自检：外部连接与少量模型测试 / 3 查看上次自检结果（缓存）/ 4 修复本次发现的可自动修复问题 / 5 导出脱敏自检报告 / 0 返回`。

`1` 等价于 `crispai doctor --local`，检查当前依赖、命令归属、每个应启用容器、数据库应用认证、AnythingLLM Key/Prompt/知识对账、n8n 生产 Code、Provider 适配器、持久任务、资料未应用变化及日志容量/清理调度，不访问外部业务服务。默认 `crispai doctor` 另对已配置的 Crisp/公网入口做有界只读检查；不执行模型推理。暂无客户流量不等于扫描失活；永久人工也不会被当作过期日志清理。

`2` 等价于 `crispai doctor --full`，增加少量合成模型调用，可能计费；不会向客户发送消息。`3` 明确显示上次结果的时间与缓存标识。`4` 等价于 `--fix`，先列出计划，只补确实缺失的受支持依赖、启动本项目已停止服务、修复受管入口/权限，然后重新检查；不会更换业务 Key、重置数据库、删库或解除人工。需要完整恢复时仍去选项 13。

`5` 把结构化白名单结果导出到受限 `logs/doctor-时间-进程号.json`。命令 `crispai doctor --json` 的 stdout 只有 JSON，可组合 `--local` 或 `--full`；普通输出和缓存文件包含检测时间、范围、耗时、观察摘要及修复建议。默认总预算 90 秒，可用 `--timeout 120` 调整到 1～600 秒；显式修复单独获得有限维护预算。

“会话状态隔离”表示最近一次扫描发现了超限、坏 JSON 或无效结构的个别会话文件。它会列为关键故障，但只显示匿名分类数量；其余合法会话仍继续调度。`--fix` 不会删除这些文件、解除人工或补发旧消息。“扫描心跳恢复记录”表示仅有调度元数据曾被安全重建：24 小时内为警告，之后作为历史记录显示；会话状态没有因此被删除。

退出码：`0` 本范围无警告/故障；`2` 有警告或待接入；`1` 有故障；`64` 参数错误；`130` 中断。菜单会展示非零结果并允许返回。安装/升级按本地关键故障决定失败，外部待接入不会被机械当作必须重装。`PASS` 仅代表本次该项有证据，`WARN` 表示待接入/处理中/不确定，`FAIL` 表示明确故障，`SKIP` 说明本次不适用或因上游不可用未检查。

示例：登记 Hook 后选 `2`，检查当前凭据绑定的接收事实；数据库认证失败则按建议核对成套恢复，不能只凭容器 running 判正常。客服主动停用、欢迎关闭、0 秒永久人工和合法外部反代均为业务状态，不会被自检改成另一种设置。

## 3. 第三方 AI 接口

子菜单：`1 查看主备接口列表 / 2 配置主接口 / 3 添加备用接口 / 4 编辑接口或模型 / 5 调整备用顺序 / 6 启用或停用备用接口 / 7 设置主接口（原主自动转备用）/ 8 删除备用接口 / 9 显式测试指定接口 / 10 主备切换策略 / 11 查看近期切换记录 / 0 返回`。

最多 1 个主接口和 20 个备用接口，停用项也占名额。没有备用是合法配置，初始化仍只需原有十项主要输入，不强求备用。列表按显示名称和数字选择；内部稳定编号不出现在普通结果中。查看列表、近期记录和刷新主菜单不发起付费模型探测。

明确选择 `3 → 1` 才有界回读适配器状态与近期记录，中文显示文本/视觉健康、剩余冷却、当前配置下可核对的最近成功及下一请求优先候选；未检测、未知或读取失败会说明原因，主菜单刷新不联网。

`2` 编辑当前主接口，`3` 先填备用显示名称、地址和隐藏密钥，`4` 按数字选择任一接口。编辑页为 `1 名称 / 2 地址 / 3 替换密钥 / 4 获取并选择模型 / 5 手填模型 / 6 请求协议与图片能力 / 7 自定义请求头 / 8 上下文与输出限制 / 9 验证并保存整组修改 / 0 取消`。所有修改先留在本次候选；`9` 再数字确认才验证并保存。改备用模型不会改主接口。密钥回车保留，数字 `0` 取消本项；新增密钥必填。请求头值隐藏输入，使用 `1 修改 / 2 删除 / 0 返回`，不能覆盖受管认证或协议头。

地址须为服务商 API 基址，保留合法代理前缀，不填完整 `/chat/completions` 或 `/responses` 路径。地址末尾缺少 `/v1` 时只追加一次：例如 `/api` 规范为 `/api/v1`，已有 `/api/v1` 保持不变，不会形成 `/api/v1/v1`。模型每页最多 15 项：`1～15` 选择、`16` 下一页、`17` 上一页、`18` 搜索、`19` 手填、`0` 返回。模型列表每轮最多三次有界请求，仍临时失败可数字重试；这不增加模型推理调用。没有可用列表可手填准确模型原名；鉴权失败先修地址和密钥。选模型仅更新候选，不立即保存。协议与图片能力在编辑页 `6` 中分开选择；启用图片能力时，保存必须通过文本和图片验证。主备菜单 `9` 的显式测试只测试所选接口，不会自行启用其图片能力。

保存和显式测试可能发出少量合成请求、产生费用，但不向客户发送消息。后端只验证所选协议；`/models` 成功、手填模型或 HTTP 200 都不能替代有效推理正文。整组候选先验证，再写齐新秘密代、原子发布有效投影，并让运行 adapter 回读相同 revision；任一步失败都保留或以新代次恢复上一整组可用地址、Key、模型与协议，界面不会把候选已写成“已应用”。正常故障切换不重启服务或重建向量，不清空永久人工状态；只有管理员修改导致知识聚合上下文预算变化时，才短暂重建本实例 AnythingLLM 并回读，界面区分保持原值、已应用及安装阶段待验证。

普通菜单按安全错误类别给出下一步，不回显上游正文或请求对象：鉴权失败、模型/端点不可用、Chat Completions 与 Responses 协议不匹配、空正文/非 JSON/结构错误、频率限制、额度不足、推理超时、上游服务端故障、DNS/TLS/容器网络连接失败，以及本地 Provider adapter 未运行。无法可信分类时只显示“原因未能分类”并引导自检；不同错误不会再统一压成“当前模型、协议或最终应用容器路径调用失败”。

`5` 按逗号填写全部备用的数字序号，每项恰好出现一次，停用项也必须列入。`6` 仅操作备用；`7` 将所选接口启用并设为主，原主原子转为备用。不能直接删掉或停用主接口，先设其他主。`8` 删除所选备用需确认。

`10` 的 `1～7` 分别设置问题总期限、单次请求期限、连接期限、总调用次数、初始冷却、最长冷却和全池冷却。默认依次为 90000 毫秒、20000 毫秒、5000 毫秒、21 次、60000 毫秒、300000 毫秒、3000 毫秒；页面逐项列出允许范围。连接期限不能超过单次期限，单次不能超过问题总期限，初始冷却不能超过最长冷却；整组无效不会保存。

高级文件操作也在 `10`：`8 查看资料文件路径 / 9 校验并应用已编辑主备资料 / 10 导入不含密钥的主备结构 / 11 查看、补全或应用导入草稿 / 12 恢复中断的知识上下文配置`。可编辑来源为 `config/provider-pool.yaml`，受管有效投影 `config/provider-pool-applied.json` 不可手改。所有接口秘密由受限代次文件管理，不放进可编辑池、工作流或普通输出。`12` 先数字确认，恢复上一份成套窗口/接口配置，不抢占尚未结束的应用；失败仍保持保护，没有事务则不操作。详见[上下文与恢复](CONFIG.md)。

导入时，同一稳定接口编号保留本机密钥；陌生备用缺密钥会停用。陌生主接口缺少本机密钥时，导入只保存草稿，当前有效池继续工作。到 `3 → 10 → 11 → 2` 数字选择草稿接口、补隐藏密钥、`9` 验证保存；这一步仍只是草稿。最后在草稿菜单选 `3` 并确认，才验证并应用整份草稿。草稿中需手填提供方准确模型原名，不能借用当前主接口刷新模型。缺密钥的备用仍保持停用，不会被当作可用后备。

示例：同供应商换主 Key：`3 → 2 → 3` 输入新 Key，再 `9 → 1`；新增备用用 `3 → 3`，手填或获取其模型后再确认。若同时换地址、Key、模型和协议，先在同一个候选编辑页完成全部修改，再保存，不让旧模型阻挡新地址的设置。

## 4. 客服提示词

子菜单：`1 查看当前 Prompt 与状态 / 2 直接粘贴多行正文 / 3 从文件导入 / 4 终端编辑候选正文 / 5 恢复上一版 / 6 导出当前 Prompt / 7 合成问题验证 / 0 返回`。

正文保存到 `config/prompt.md`，历史在 `backups/config-history`。文件路径可含中文和空格，须为普通可读文件；不支持符号链接。编辑器只在现成 nano/vi 可用时使用，否则粘贴即可，不要求另装。Prompt 上限 256 KiB，导出不覆盖已有目标。

示例：`4 → 2`，粘贴“优先依据当前知识回答；不知道时简短追问。”，输入 `::END::`、`1`，再选 `7` 输入虚构问题。保存后核对 AnythingLLM Prompt 和 n8n 可读正文；同一旧 conversation 的下一问使用新 Prompt，无需新建聊天或重启全栈。同步失败恢复上一版；自定义 Prompt 不能取消鉴权、总开关或人工控制。

## 5. 多知识库管理

子菜单：`1 查看知识库及索引状态 / 2 创建命名知识库 / 3 重命名知识库 / 4 粘贴知识正文 / 5 导入文件或目录 / 6 查看/删除指定条目 / 7 启用知识库 / 8 停用知识库 / 9 删除知识库 / 10 同步知识库 / 11 重建索引 / 12 生产问答测试（全部启用库，可能计费） / 0 返回`。

`2` 输入名称，程序生成并内部保留稳定编号，普通列表显示名称；`4` 数字选库、输入条目名、粘贴多行正文；`5` 选库后输入 MD/TXT/PDF/DOCX 文件或目录。支持中文、空格与大写扩展名。单文件须非空且不超过 50 MiB；目录需普通文件。`6` 先选库再数字选条目，确认后删除；`9` 删除库需确认。`10` 同步和 `11` 重建可选全部或指定库；`12` 始终按实际客服的范围使用全部已启用库，不伪装成单库问答。重建会重新索引并增加计算与下载耗时，普通更新优先增量同步。

`knowledge/catalog.json` 记录名称、ID、启用状态、文档与版本；`knowledge/kb_*/sources` 保存原文；manifest 与 workspace 文档映射用于真实对账。库启用后共同服务于一个客服 workspace，客户上下文不被拆散。同库同名文件用于更新同一条目；跨库同名文件独立。同内容在不同库按独立归属管理，删除一库不误删另一库。

停用保留原文但从新检索移除；删除移除当前库定义和原文，恢复副本仍可能在受限配置历史或备份中。索引尚在处理时显示 pending/错误原因；不要反复删库，选同步继续对账。失败保留或恢复旧有效版本。历史聊天里已出现的旧事实不会因此自动抹除，政策变动应在新 Prompt 中明确以当前知识为准。


示例：用 `5 → 2` 分别建立“订阅使用”“电脑排障”“手机排障”；各用 `4` 粘贴虚构事实，`12` 先用完整 FAQ 原问，再用中文改写问题。该操作发起一次与真实客服相同的逻辑问答；若发生故障切换，可能依次调用一个或多个已启用上游并分别计费。它不创建客户会话、不向 Crisp 发消息、不写业务统计。再用 `8` 停用其中一库，核对该库不再出现于新来源；其他库应不变。不把上传成功或模拟模型固定回答当作真实语义检索证据。
## 6. 关键词与按钮

子菜单：`1 查看规则 / 2 创建规则 / 3 修改规则 / 4 启用规则 / 5 停用规则 / 6 删除规则 / 7 输入客户文字预演 / 0 返回`。

规则编辑包含名称、关键词（英文逗号分隔或 `::PASTE::` 逐行）、排除词（`::CLEAR::` 清空）、包含/完全匹配、动作、优先级、冷却秒数、按钮有效期、正文及按钮/确认文案。优先级越大越先；同优先级按稳定规则排序。动作是人工确认按钮、固定回复、多级菜单或知识问答。人工按钮默认冷却 60 秒、有效期 600 秒。

示例：`6 → 3` 选择人工确认规则，词表 `人工,转人工,人工客服`，包含匹配，保留“不要人工”等排除词，按钮填“召唤人工客服”，保存；再用 `7` 预演“我想转人工”和“不要人工”。预演不发真实消息。

`config/keyword.yaml` 保存规则原文，菜单保存并应用后，工作流逐次读取生效投影，无需重启。直接编辑文件则须显式应用。命中仅发送真正 picker，消费本条关键词消息、不再附加一份普通答案；未点击而继续提问仍由自动客服处理。点击有效按钮才暂停当前 conversation；默认“继续咨询”不暂停。文本冒充按钮、跨会话、重复及过期点击无权接管。旧直接 handoff 规则在升级时迁移为确认按钮。

## 7. 人工接管与恢复

子菜单：`1 查看恢复设置 / 2 修改恢复秒数 / 3 查看当前人工会话 / 4 手动恢复指定会话 / 5 调整指定会话倒计时 / 0 返回`。

`handoff.resume_after_seconds` 位于 `config/handoff.yaml`。新装及字段缺省为 3600，范围 0～604800 秒；`0` 是不自动恢复，不是立即恢复。升级保留已有合法显式秒数，包括旧 1800 和 0。正整数从首次有效确认按钮或最近一次新的真人公开回复计时；访客消息、自动确认、重复/乱序旧事件不重置。设置默认值只影响之后的接管/真人新回复，现有截止时间保留；`5` 明确选中某会话才从现在重新计时。

示例：`7 → 2 → 300` 设五分钟；`3` 看原因与剩余时间；`4` 按数字选 A、确认恢复，不影响 B。A 在 t0 由真人回复，t6 再回复且设 10 秒，则 t16 前不恢复；到期仅回答下一条新问题，不补答旧消息，也不发恢复通知。5 秒持久扫描并结合消息到达时校验，重启不丢截止时间。

永久人工状态不会随普通去重缓存清理。v1.0.1 旧状态只保存 session 哈希，首次该会话再来事件时惰性迁移并保留人工；尚未再来事件的旧哈希不能在菜单中凭空还原出会话名称。真实人工公开文件/图片也接管，内部 note、在线、已读、打开后台不接管。

## 8. 客服总开关

子菜单：`1 启用自动客服 / 2 停用自动客服 / 3 查看当前状态 / 0 返回`；等价命令 `crispai enable` / `crispai disable`。

修改 `config/runtime.yaml` 并使旧任务代次失效，不重启容器。关闭时 AI、规则、欢迎和普通错误提示均静默，Hook 鉴权和真人状态记录仍运行。自动评价邀请无论总开关状态都已停用。重新打开保留 A 的人工期限，B 可继续 AI，不补答停用期间历史。

总开关不等于停止容器、不等于所有会话转人工、不隐藏 Crisp 聊天框、不影响真人。维护停机见选项 16。

## 9. 欢迎语与多级菜单

子菜单：`1 查看欢迎配置 / 2 启用欢迎 / 3 关闭欢迎 / 4 粘贴多行欢迎文案 / 5 选择触发方式 / 6 设置自动展开聊天框 / 7 设置欢迎附带根菜单 / 8 多级菜单管理 / 9 查看无密钥页面接入片段 / 0 返回`。

`5` 选 `1 首条访客消息 / 2 页面加载 / 3 访客打开聊天框`。后两项及自动展开需要把 `9` 的无密钥片段接入网页一次，详情见 [CRISP](CRISP.md)。发送欢迎不等于浏览器展开；自动展开使用官方 `chat:open`。配置获取失败时不强制展开。

`8` 的菜单树子菜单为 `1 查看/预览 / 2 新建节点 / 3 修改标题 / 4 新增/修改按钮 / 5 删除按钮 / 6 删除节点 / 7 设置根菜单 / 0 返回`。新建选父级自动建立导航；按钮输入数字、标题、动作及排序。支持下级菜单、固定回复、知识问答、人工确认、返回父级；每节点最多 12 个选项（含返回），最多从根向下跳转 8 次，下级环、无效引用或越界会被拒绝。删除节点前先移除引用。

示例：`9 → 4` 粘贴“您好，请说明遇到的问题。”、保存；`2` 启用、`3` 关闭分别验证。用 `8 → 2` 建“电脑标准排障”等节点，问答内容从自己的知识库取得，不将示例当成经营承诺。

## 14. 更新与回滚

子菜单：`1 匿名在线更新至最新正式版 / 2 从已解压的新版本目录离线升级 / 3 从原 Git 源码更新（高级） / 4 查看历史快照 / 5 回滚指定快照 / 0 返回`。

推荐选择 `1`，再输入 `1` 明确确认。它调用受管部署内的 `get.sh --update`，匿名解析公开仓库当前 Latest，先锁定一个正式 tag，再下载该 tag 的完整包与 `SHA256SUMS`；只有 Release 状态、唯一资产、校验和与安全归档检查全部通过后才调用原有更新器。无需 Git、`gh`、GitHub 登录、浏览器下载或手工解压；已经是最新版时不改动实例。更新前仍由更新器创建一致性快照，失败自动回滚。

`2` 是已有可信离线包时的高级入口，输入完整解压目录；`3` 只适用于部署标记记录的原 Git 工作区仍可访问的维护环境，不建议普通用户直接跟随 `main`。`4` 按版本与时间查看历史快照；`5` 数字选择快照，再确认恢复，内部编号由程序处理。维护期间不能接待新消息，完成后用 `crispai doctor` 检查。旧人工状态、秘密、Prompt/知识按迁移与快照规则保留，已发旧按钮可能因代次变化失效；在线检查或下载失败不会覆盖当前实例。

## 15. 日志与故障排查

子菜单：`1 日志来源、占用与保留策略 / 2 按来源查看最近日志 / 3 持续查看指定来源 / 4 轮转或清空选定受管日志 / 5 删除指定天数以前的历史日志 / 6 修改保留天数与容量限制 / 7 按当前策略立即清理 / 8 导出脱敏诊断包 / 9 排障说明 / 0 返回`。

`1` 区分维护事件、自检缓存/历史、四个主要容器、可选 Caddy、系统级清理单元、n8n execution 和 analytics；显示能够取得的占用，Docker 内部文件不可安全读取时明确未知。`2` 数字选来源、输入 1～2000 行及可选窗口（如 `30m`、`2h`、`7d`）；高级 `crispai logs show` 允许 `--lines 1～10000`。n8n execution/analytics 只展示各自保留策略，不输出业务正文。`3` 的 Ctrl+C 只停止查看并回菜单，不停止服务。

`4` 只允许维护事件、自检缓存和自检历史；先预览、再输入 `1` 确认或 `0` 取消，清空不可恢复。维护事件还可选择轮转。`5` 输入 1～3650 天，预览数量/空间后确认；`7` 立即按当前策略清理，均不处理知识、备份、人工/offer/jobs、analytics 或数据库 WAL。不存在“清空 Docker 内部文件”功能，不执行全局 prune 或 journal vacuum。

`6` 修改文件保留 1～3650 天、每份 1～1024 MiB、最多 1～20 份，预览后明确确认。新安装默认 7 天、10 MiB、5 份；升级保留已有合法策略（旧默认容器为 3 份）。轮转份数包含当前文件，5 份即当前加最多 4 份历史；自检历史最多保留 5 个独立快照。文件历史由本实例系统级 timer 过期清理；Docker 按每容器容量轮转，**不是精确保留 N 天**。n8n execution 另由其官方保留机制负责，成功和失败节点正文默认均不保存。改变容器日志容量要重建本项目容器，会短暂停机；保存后实际配置回读，失败恢复旧策略，不重置业务资料或会话。

`8` 导出受限 `logs/diagnostics/crispai-diagnostics-*.tar.gz`，仅带白名单自检、版本和裁剪日志摘要；不含 `.env`、完整 Hook URL、聊天、截图、Prompt/知识或数据库。展示日志仍可能有业务错误线索，不要直接公开转发。示例：`crispai logs show n8n --lines 100 --since 30m`；自动化清理先用 `crispai logs cleanup --preview`，明确 `--apply` 才删除。操作退出 0/2/1/64/130 含义与本次结果提示一起阅读。

## 16. 服务与依赖维护

子菜单：`1 启动本项目服务 / 2 停止本项目服务 / 3 重启本项目服务 / 4 检查依赖与 Docker / 5 自动修复依赖 / 6 校验并应用已编辑资料 / 7 修复 crispai / crisp 入口 / 8 查看用户资料路径与未应用变更 / 0 返回`。
