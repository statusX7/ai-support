# v1.2.1：取消自动评价邀请、主备接口池与中文管理

本版保留 Crisp、n8n、AnythingLLM、PostgreSQL 与原有客服控制规则。下文说明代码能力和安装流程；TARGET-A 同包、正式发布及匿名核验结果由同 Release 的独立 `v1.2.1-verification.md` 回执证明，未取得相应回执不能把本页当作验收完成证据。

## 主要变化

- 不再自动追加评价文案、评分链接或评价按钮；新装、升级、重复初始化与旧业务导入均停用邀请。旧待评价状态不消费新的“是/否/👍/👎”，历史统计保留只读，人工 offer 和普通待处理任务不清空。
- 发送者使用中性“在线客服”，不额外添加“机器人/AI 回复”后缀，不请求可选 automated 徽标；发送前持久登记自有 fingerprint，兼容旧回流且不依赖昵称猜真人。平台实际显示由 TARGET-A 同包 SDK 验收证明，不能以代码字段推断标签已消失；直接被问身份时如实说明自动客服。
- 主菜单 3 管理 1 主、最多 20 备，总计 21 项，停用和草稿也占名额。十项初始化只填主接口，没有备用合法。旧地址、Key、模型、协议和自定义头迁移为主接口，不重问多套凭据。
- 非秘密池源、原子有效投影和受限秘密代次分离；只有 adapter 挂载全池上游秘密，n8n/AnythingLLM 使用独立内部认证。旧 `.env` 单接口字段只是兼容投影。
- 按配置顺序处理可恢复接口故障，文本与图片两阶段共享问题预算：默认 90 秒、最多 21 次，单次 20 秒、连接 5 秒；不为安全拒绝或明确输入错误切换，也不修改 workspace、重建索引或转人工。
- 普通菜单用中文摘要显示真实业务状态，关闭欢迎不再混用总开关回显；18 主菜单、数字返回/取消和显式结构化脚本接口保留。
- `crispai apply --check` 先校验业务和池源；明确 `crispai apply` 才应用。业务已成功但池失败时分别报告，保留业务新值和上一有效池，不假称整体成功。

主备切换可能把必要 Prompt、知识、同会话公开历史或图片发送给另一个可信服务，并增加费用；添加前确认授权与余额。没有后台持续付费轮询。默认冷却 60～300 秒，不截短更长的上游 `Retry-After`；完整限制见[配置说明](https://github.com/statusX7/ai-support/blob/main/docs/CONFIG.md)。

## 已安装实例与迁移

正式发布后用 `crispai → 14 → 1` 更新；升级前一致快照，失败按实际恢复结果处理。受管 `crisp` 兼容入口继续与 `crispai` 共用管理器，入口单独损坏仍用同版本 `get.sh --repair` 的窄救援流程。

欢迎、总开关、人工恢复 1800/0 或合法自定义值、Prompt、知识和会话控制保持；自动评价邀请是本版明确停用项。业务包不带上游 Key/请求头值：未知主接口先存草稿而不替换当前池，缺 Key 的新备用保持停用，补齐验证后显式应用。完整本机快照则包含恢复所需秘密与状态，不能公开。

## 验收与发布状态

验收采用固定顺序：冻结完整包 → 本地真实组件与授权 TARGET-A 同包验收通过 → push/tag/draft/Release → 匿名回下载、空机安装与目标机正式同包核验。任何生产差异都须重新核对完整候选；真实是否通过、失败边界及正式资产身份以独立回执为准，不由这份能力说明替代。

本轮 F8+A28+U12+R14 合计 62 个验收场景，场景清单不等于已通过数；协议 fixture 不等于真实多家账号，构造的 `automated:false` 不等于后台真人操作。最终结果、原始失败与外部边界由该版报告和独立 `v1.2.1-verification.md` 回执逐项记录，不引用 v1.2.0 历史成功填充本轮结果。
