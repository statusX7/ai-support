# 架构与运行契约

## 组件职责

| 组件 | 职责 |
| --- | --- |
| Crisp | 访客聊天框、公开消息、真人界面与事件 |
| n8n | 已鉴权持久接收、短事务控制、规则/欢迎、发送与恢复扫描 |
| AnythingLLM | 文档解析、Embedding、workspace 向量检索与索引对账 |
| Provider 适配器 | 同一项目的主备路由、跨阶段预算与 Chat→Responses 最小兼容，不自建 RAG |
| 第三方 AI | 实际文本与可选视觉推理 |
| PostgreSQL | n8n 配置、工作流与其必要数据库 |
| 可选 Caddy | 受管 HTTPS，仅开放指定 Hook/SDK/UI 路由 |
| Shell 管理器 | 单一配置权威、应用/回读、安装维护与全局 crispai |

不增加 CRM、多租户、坐席调度、Redis/Kafka、另一套向量库或管理网站。

## 安装链路

```text
匿名 get.sh → 锁定正式 tag/完整包校验/安全解压
→ install.sh 参数/帮助 → root/sudo → 最小工具自动补齐
→ 识别首次/续装/已部署 → 十项向导 → 用户确认
→ Docker/Compose/daemon/实际容器能力
→ 受管目录和内部密钥 → 固定镜像与服务
→ AnythingLLM Key/workspace/Prompt/多库索引
→ n8n import/publish/生产节点 → 配置回读与代次
→ crispai/可选 crisp 入口与系统级日志 timer
→ 本地/Provider/Crisp/公网/会话分层事实
```

所有持久数据在选择的部署目录，默认 `/opt/crisp-ai`；程序来源解压目录可删除。系统包、Docker 服务、受管命令和本项目 `/etc/systemd/system/crispai-log-maintenance-*.{service,timer}` 是明确受控的系统位置例外，不依赖临时排障用户的 HOME/登录或用户 cron。帮助/版本不要求完整配置或外部探测。`get.sh --repair` 用同版完整正式包校验后修复命令归属，不初始化/替换客户资料；完整程序更新仍走显式 `--update`。

## 事件、控制与发送

```text
Crisp Webhook
  → Secret/签名、website/session、大小与事件去重
  → 持久保存任务；人工/合法按钮控制短事务优先提交
  → HTTP 确认
  → 持久任务处理：总开关 → 会话模式/到期 → 旧评价退役/菜单/关键词
  → 当前问题先查受管精确/近似词法索引；其余问题单独交 AnythingLLM 向量检索（图片先提取事实）
  → 完整相关片段 + 当前 Prompt + 本会话公开历史 → 受管模型适配器
  → 全局 revision + 会话 generation + 当前人工状态再次检查
  → 统一受管发送 / 预登记 fingerprint
  → 发送确认后统计、可选标签；超时未知先查列表及精确 fingerprint
```

另有 n8n 5 秒 Schedule 恢复未完成任务与到期状态。`runtime.js` 为唯一生产实现，由 `build-workflow.js` 内联进工作流，并由容器 CLI 复用；生成校验防止 JSON 模板与逻辑分叉。

控制状态 `data/runtime/session-SHA256(website+NUL+session).json` 使用短 mkdir 锁、fsync/原子写，并在写前执行与读取一致的 2 MiB 字节上限；普通入站在硬上限前保留处理余量，拒绝时不替换原文件。每会话普通消息队列有序，不在长 LLM 请求期间持锁，不同会话独立。周期扫描每个会话每轮最多选择一项，以持久游标在普通任务和人工控制之间轮转；单个坏 JSON、超限或内层结构损坏的会话只被匿名隔离，不再中止其他会话扫描。扫描锁使用完整 claim 原子发布、进程启动身份和心跳，严格识别并回收崩溃残件；普通心跳元数据损坏可重建，但链接和特殊文件失败关闭。全局开关来自资料投影中的 runtime.enabled，不是共享人工状态。无限人工不受已完成任务缓存淘汰影响。生成投影损坏、资料应用中或知识映射代次不一致时，不继续用半份原文发送普通回复；已接收问题持久延后，资料成功发布后按最新代次恢复一次。期间发生真人接管或总开关关闭仍永久取消对应问题。人工事件始终走持久控制路径，并在容量压力下优先收缩已取消的普通任务后提交暂停代次。

Crisp POST 已交出字节但回执未知时，原正文、计划和 fingerprint 保持绑定。重试前先查会话消息列表；列表可能短暂滞后，因此 10 秒后还必须查询精确消息端点。列表成功后，精确端点的 404 只算一次“未找到”；其它鉴权、限流、服务或网络失败仍是未知。仅在两次至少间隔 5 秒的明确阴性结果后，才允许同 fingerprint 再发送一次；查询失败只继续对账。配置换代时同样先收敛旧 fingerprint，避免按新规则产生第二条答案。人工确认通知属于受限控制消息：会话已正确进入人工模式不会让它自行失效，但总开关关闭或会话代次变化仍会取消。两次 POST 结果均未知时在五分钟窗口内只对账，超时记录明确送达故障；跨系统仍不宣称绝对 exactly-once。

v1.2.1 的访客昵称与内部身份分离：Crisp POST 前在同一会话短锁内，将本项目 fingerprint 登记到 `data/runtime/owned-<会话摘要>-<分桶>.json`，再记录发送任务。使用官方可选中性昵称，不请求自动消息徽标；识别自回流不依赖昵称、正文或该徽标。索引只含 schema 和指纹，不含消息正文；每会话按低 8 位分为最多 256 桶，每桶最多 50000 条、读取上限 1 MiB。详细出站记录清理不删除身份索引，它随完整快照保存，不进入业务迁移包、日志清理或公开报告；损坏/超限时拒绝相关出站，而不猜测真人身份。历史 `automated=true` 继续兼容，未登记的真人公开回复照常优先暂停该会话。

关键词只发 offer，仍处 AI；有效点击先暂停再确认，真人公开回复无需按钮立即暂停。倒计时从最近有效真人/首次确认开始，新装及缺省为 3600 秒，0 永久，已有合法显式值保持，用户消息不延长；到期只允许新问题，不补历史、不发恢复提示。自己的自动出站、note、在线、输入和后台 opened 均不当真人。

## Prompt、知识与上下文

各命名库用 catalog/document ID/hash 管理，全部启用库汇入一个 workspace。原文、投影、远端位置与 runtime 来源映射分离；停用库真实移除检索关系但保留原文，删除或更新不误操作其他库。pending 对账承接服务端索引超时，不能只看 HTTP 上传成功。

公开 Crisp 历史是唯一对话上下文来源，按当前会话限定与限量；人工回复显式加入，内部 note 和控件不当业务问题。不再叠加 AnythingLLM 内部聊天历史。当前 Prompt 仍同步回读 workspace；运行时文本和图片请求均读取同一生效投影中的完整正文。

固定组件的 `/chat` 会把整个 message 同时用于 Embedding 和生成，且 sources 的记录早于上下文压缩。v1.2.1 因此复用其 `/api/v1/workspace/:slug/vector-search`：只提交当前问题，采用 workspace 的实际检索数量、阈值和模式，不把内部护栏、HMAC 信封或整段历史当成检索词。同时从当前启用映射所指向的 AnythingLLM 已解析正文生成有界词法索引；完整问题或足够具体的短语命中时直接保留对应完整问答块，普通改写则与向量结果合并并去重。索引与映射、解析正文、资料投影的哈希必须同代，任一篡改或旧代都拒绝使用，不会把停用库重新带回。

`prepareKnowledgeContext` 将确属当前启用库的完整片段、原 Prompt 和同会话历史分开传给既有 adapter；签名通过内部 Header 传递。未知/停用或歧义来源、畸形响应、超出容量均拒绝，不把错误写成知识未命中。资源足够且没有管理员显式固定模型的旧实例，会在受限保全后迁移到固定的多语言 Embedding 配置并用 400 字符块重新索引；资源不足时保留原模型并继续使用受管词法补召回。迁移失败成套恢复或保持停发，不让新模型读取旧向量。没有新增向量数据库或外部检索服务。

`n8n/admin-query.js` 由受控 Shell 经容器 stdin 调用，与客服共用这条检索/生成链。显式管理员测试不创建 Crisp 会话、不发客户消息、不修改业务统计；普通 Webhook 无管理员授权。空知识连接测试的模型成功仅说明可调用，不证明知识命中或答案正确。每次检索后及模型/发送前均复核配置与会话代次，人工控制不等待模型。

准备的片段不做静默截断；每块最多 1 MiB、总正文最多 2 MiB、最多 20 块，HTTP 响应本身另有 2 MiB 上限。模型上下文窗口更小时，由接口池按完整输入估算后选择容量足够的候选或准确失败，不能删掉知识后声称知识库没有答案。文件上限不等于模型 token 上限。协议服务只能证明格式接线，真实中文检索与最终回答语义另行验收。

AnythingLLM 的受管预处理窗口由已启用、非草稿且协议已确认条目的最大配置窗口派生，每个上游仍执行各自上限。配置变更仅在该聚合值变化时重建本实例 AnythingLLM，核对实际容器环境和鉴权 API；正常主备故障切换不重建。窗口事务及失败恢复期间保护普通推理和旧输出，人工控制继续持久接收。最终文本请求按当前资料代次核对完整 Prompt，不能用 workspace 已保存全文代替真正上游载荷的保真证明。

## 欢迎网页边界

first_message 无需网页变更。widget_load/chat_open 模式用一次性无密钥 SDK：session:loaded/chat:opened → session:event → Crisp session:sync:events Hook → 后端受控欢迎。chat:open 独立控制展开；公开配置仅白名单字段并结合会话人工状态，不能匿名接管或向别的会话发送。

## 配置和维护

业务 YAML/JSON、Prompt 与多库原文是权威源，实例秘密在 `.env`，多接口秘密在受限 `secrets/provider/` 分代保存。`materials.sh` 统一菜单与直接编辑的应用：严格 UTF-8/大小/schema/引用校验→有效版本备份→规范化候选→实际 API 同步→组件回读→发布 `config/materials-applied.json`。用户无需编辑 manifest 或 Code。Prompt/索引慢同步先发布 `applying` 代次，使旧 AI 结果失效；失败恢复上一份有效资料和外部应用，回退未确认则保持保护状态。配置/知识根目录原 inode 保留，避免容器仍绑定被挪走的旧目录。

| 内容 | 稳定位置 | 修改方式/消费者 |
| --- | --- | --- |
| Prompt / 业务规则 | `config/prompt.md`、受支持 `config/*.yaml` | 管理员编辑；materials 校验生成投影，运行时只读已应用版本 |
| 命名库原文 | `knowledge/kb_*/sources/` | 菜单或直接编辑现有条目；新增/删除用知识管理保持归属 |
| 库定义 | `knowledge/catalog.json` | 可编辑已登记库名/启用状态；稳定 ID/source/projection 由管理程序维护 |
| 索引关系 | `data/knowledge-manifest.json` | 实际索引对账，由程序维护，不手改 |
| 生效资料 / 检索来源映射 | `config/materials-applied.json`、`data/runtime/knowledge-map.json` | 应用后原子发布，运行时验证映射代次 |
| 接口池及生效投影 | `config/provider-pool.yaml`、`config/provider-pool-applied.json` | 单一池源，成套候选验证、秘密引用及热加载 |
| 窗口维护事务 | `config/provider-pool-transaction.json` | 程序维护的受限保护记录；只从显式恢复入口处理，不手删 |
| 秘密 / 会话控制与任务 | `.env`、`secrets/provider/`、`data/runtime/`、`data/provider-router/` | 受限解析/短事务；不是日志清理对象 |
| 维护事件 / 诊断历史 | `logs/` | 白名单事件、脱敏导出与系统级 timer |
| 恢复资料 | `backups/` | 完整敏感快照与业务迁移包分开，不上传 |

普通 `apply` 对无变化原文快速返回；显式 `--force-external` 同步并回读现有 Prompt 与启用知识的受管位置关系，不默认全量重索引，也不承诺逐字审计远端解析正文或删除非受管文档。维护串行锁与会话控制锁分开。完整本机快照包含秘密与运行状态；业务迁移包含全部库原文而不带会话/Key。旧关键词迁移为按钮确认，旧哈希人工记录惰性迁移不清空。

## 日志与保留

Shell 生命周期只记录操作/阶段/退出码等白名单字段，不 tee 隐藏输入或 HTTP 原文。运行时异常在落盘前归类，不保存客户端异常对象；n8n 工作流关闭成功/错误执行正文和进度保存。容器使用受管 `json-file` 大小/份数策略，变化要重建本实例容器并回读。受管 Caddy 不启用访问日志，并过滤默认运行错误日志的请求 URI/认证头；外部反代的日志保护需管理员实际合入、重载并验证，见 [CRISP](CRISP.md)。应用日志、Docker 容量日志、n8n execution 数据与 analytics 是不同来源，策略不能互相冒充。

`logs.sh` 与菜单 15 共用来源白名单、预览/数字确认、轮转、过期清理与脱敏包。系统级 timer 在开机后及周期内调用同一清理器，不依赖 n8n 是否运行。它不删除 Docker LogPath、系统 journal、数据库 WAL、向量索引、备份、客户任务或永久人工状态。

安全卸载移除项目容器/网络/程序与所属全局命令，保留数据；完整清理先外部完整备份再数字双确认。回滚重建数据目录绑定容器，保留历史镜像身份。任何容器、库、网络、Key 或账户缺失不能靠改状态标志变成成功；外部验收分层见 [TESTING](TESTING.md)。
