## 实际协作

主 Agent 负责公共配置、Compose、推理与取消接线、doctor、资料应用、迁移、快照回滚、集成和发布。执行 Agent 按并发容量分批协作：

| 职责 | 实际产出与所有权 |
| --- | --- |
| A 多接口 | adapter、router、签名信封、接口池管理后端及协议测试 |
| B 中文 UI | manage、展示层、主备菜单、真实 PTY 和 MENU |
| C 评价与独立回归 | 精确退役旧评价状态，保留未知出站对账，配置/生命周期独立测试 |
| D 实机与文档 | 唯一 TARGET-A 操作者，受限现场备份、复现及候选验收，操作手册 |

共享文件由主 Agent 集成，目标机不并发变更；任何 Agent 自述通过均不替代最终集成复验。

## 接口池与费用边界

非敏感定义与秘密分离，稳定 ID 不随改名/排序变化。停用备用仍占容量；设主为角色交换。旧单接口幂等成为唯一主接口，无备用合法，不要求重复填写十项向导。导入缺主凭据时只保存草稿，原有效池继续工作；同 ID 本机秘密不会被空值覆盖。

文本 RAG 与直接视觉均通过同一 adapter。每问题首次确定的预算跨阶段与重试保持：默认总 90 秒、单调用 20 秒、连接 5 秒、总 21 次；不承诺一定等到最后一个备用。正常回答、拒绝和知识不足不作故障切换。Crisp 发送/标签错误不触发重新推理。

接口配置变化、总开关和单会话接管都会作废未发送的旧结果。冷却与管理员停用分离；指数退避加入 0～5% 正向抖动，普通上限不被超过、更长的 Retry-After 不被缩短。半开试探有单租约，两次有效成功恢复。状态受限持久保存，不使用新的数据库服务。无后台付费轮询；失败或取消可能仍被上游计费。

上下文使用明确的近似 token 估算，不宣称精确 tokenizer；不静默丢弃知识或图片。不同供应商不会复用响应 ID/文件 ID/线程 ID。实际独立上游数量与 21 条目协议容量分开；TARGET-A 的真实配置数量只在受限私密交付说明中记录，不因容量测试而虚构额外账户。故障注入仅作用隔离合成任务，不能留作正式备用。

AnythingLLM 预处理窗口取启用且协议能力已确认接口的最大配置窗口，单次路由仍检查每接口上限。只有维护时聚合值变化才重建本实例 AnythingLLM，不按故障切换重建。事务中断保持推理保护，菜单 `3 → 10 → 12` 显式恢复；没有事务时不操作。窗口值是受管配置，不是官方容量承诺；保真守卫同时检查有效 Prompt 字节/hash/代次及实际上游单条系统消息中的全文。默认 doctor 只读核对事务、聚合投影、容器和鉴权 API，不调用模型、不清标记。

协议复核采用 [OpenAI 官方迁移说明](https://developers.openai.com/api/docs/guides/migrate-to-responses)：区分 Chat 与 Responses 的正文结构，按类型读取输出，使用当前会话规范化历史且设置 `store:false`。中性客服显示采用 [Crisp 官方消息字段](https://docs.crisp.chat/references/rest-api/v1/#website_send-a-message-in-conversation) 中可选的 user/nickname，省略可选 automated；界面是否有徽标仍以实际 SDK 新消息验收为准，文档字段本身不作为显示成功证据。

本报告自身不替代 TARGET-A 正式同包验收，也不单独作为撤销临时排障账号的依据。是否已正式发布、目标机是否正常接待及账号是否不再被依赖，以同 Release 核验回执和受限私密交付说明的实际结果为准。
