# ai-support v1.3.1 修复与验收报告

本报告记录实际修复与增量验收，不预填正式发布结果。最终提交、包 SHA、公开安装和 Release 地址由包外 `v1.3.1-verification.md` 记录；未取得该回执不能仅凭本报告认定发布完成。

## 基线与边界

基于已发布 v1.3.0 提交 `977d9566c5ca1f3b0513f3735b7bfd13c660629e` 开发，用户明确授权交付 v1.3.1，保留旧发布。产品修改与测试先在 TARGET-A 运行；只有全新安装使用获授权的本机隔离 VM。原开发机的未提交工作保持，不开发或修改 Haruka 等其它接入。

## 已定位根因与修改

| 问题 | 实际原因及处理 |
| --- | --- |
| 首次安装 Caddy 预检失败 | 同一安装终端中，旧 Compose 校验在容器退出 0 后仍触发 SIGTTIN 并等到 60 秒超时；配置本身合法。仅禁用预检 TTY/stdin 即返回 0。common.sh 增加 `-T --interactive=false` 和空 stdin，仍执行 caddy validate，并保留脱敏失败原因和回滚保护。首次没有可回滚代是事实，不通过假造回滚代规避。 |
| Token 无法核对 | wizard.sh 的安装 Key/Identifier 输入与 401 重输改为可见；最终摘要及日志仍脱敏。没有公开真实凭据。 |
| 模型探针误报不可用 | DeepSeek 的 16-token Chat 探针只返回 reasoning；64-token 对照有正文。管理图片探针的 64 token 也被 reasoning 耗尽；提高至候选输出上限内最多 1200 后取得正文。仍限制超时、容量并拒绝空正文，探针不替代客服或视觉准确性验收。 |
| GPT 完整问答在上游前被跳过 | 8192 配置不能容纳当前完整 Prompt、资料和输出预算。新增 doctor 基础容量检查；按用户选定值将该接口设置为 65535，正常事务回读 RAG 输入预算 64335，不截断 Prompt、不全局强改所有模型。 |
| 放开容量后仍不能调用 GPT | 实际中转对 temperature 返回 HTTP 400/明确不支持；同形请求省略该可选参数后正常。adapter 仅对这个明确错误在同候选重试一次，沿用剩余期限、取消与配置检查；身份隔离缓存一小时、最多 128 项。其它输入错误、认证失败和安全拒绝不绕过。 |

## 更正、删除及保留

首个冻结候选的真实空机安装 354.424 秒后退出 1：Caddy 与四核心服务已运行、知识已索引，但本轮新增容量自检失败。直接探针的终端对照均成功；随后复现原 doctor 的完整子 shell 与输出重定向，取得正确容量 JSON 但退出 124，关闭 stdin 后 0.376 秒退出 0。仅修该输入继承回归，不去掉门禁；旧失败与初始未复现对照保留。第一次 VM 已销毁，回收 9702789120 字节，未将其登记通过；修正版 build-002 已在剩余预算内通过空机验收，累计控制流程 758.362/1500 秒；第二次 VM、测试盘及临时密钥已销毁，回收 9679122432 字节。新增真实 PTY 容量回归 7 组通过；首轮夹具漏环境包装的失败亦保留。

一次验收脚本把业务任务与派生菜单任务的覆盖指纹混为唯一任务，误报无回复；保留原失败，通过同一会话的两次只读 GET 和真实入站 ID 更正，没有再次投题或修改应用状态。早期向导旧隐藏输入断言、测试端口占用及人工容量预期少一 token 的失败也保留，均不登记成新应用缺陷。

临时 Claude/DeepSeek 验收候选已通过受管命令删除，并恢复原 GPT 主接口、顺序、策略和逻辑凭据；本次临时含 Key 文件已清除，必要受限结果保留。没有删除业务功能、用户知识、Prompt、客户会话或人工保护，也未恢复退役评价。两次空机 VM 都已实际销毁，保留必要脱敏结果和原失败。

## 全面 debug 追加：待复核管理缺口

第三份指令继续要求当前可复核的缺陷必须修复，不以披露或豁免代替。两条现场旧咨询发生在未知 operator 控制窗口内，保持静默并保留复核责任本身符合已确认规则；实际管理缺口是此前 CLI 和菜单没有可用的复核处置入口。

现在在原 runtime、CLI 及人工菜单增加逐条显式关闭入口：仅允许尚未推理或出站的旧窗口咨询；选择摘要绑定任务及会话代次，状态变化则拒绝，重复确认幂等。关闭保留原失败原因及管理员关闭记录，不发送消息、不记成已回答、不判断未知 operator 的身份，也不改变其它任务、人工模式或截止时间。没有自动关闭现场两条咨询。

TARGET 上原控制套件新增必要正反例后 76 项通过；原管理菜单整套在 300 秒上限结束，44 项前缀通过但新用例尚未执行，原超时不改写为通过。沿用现有 MENU_TEST_FOCUS 增加定向选择，首次执行发现新增菜单取消分支返回非零、触发 Bash 严格退出的回归；仅修正取消/返回退出码，原断言保留。随后两项真实菜单→CLI→runtime 状态文件用例 4.684 秒通过，文档 6 项通过；累计 517.773/900 秒，含旧失败，不重跑已通过控制套件。

这些是 TARGET 隔离验证，不等于新入口已在当前客服容器加载。完整包应用后的身份与实际运行结果继续记录在本轮受限任务单及最终独立回执。视觉 Probe 的语义验证仍有待核查线索；全面审查未完成，不因这一局部修复提前发布。
