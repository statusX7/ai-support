## 4. 安装与配置的实际调用链

`install.sh` 参数/帮助 → bootstrap root/发行版 → 最小工具（含 jq/Python YAML/cmp/flock）→ 识别安装/恢复 → 同一十项 wizard → 确认后 Docker Engine/Compose/daemon/测试容器 → 持久目录/密钥/Compose → PostgreSQL/AnythingLLM/n8n/协议适配 → API Key/workspace/Prompt/知识对账 → workflow 导入/发布/实际 Code → 配置 revision 回读 → crispai → 本地/Provider/Crisp/公网/会话 facts。

普通文件来源主步骤：API 地址、隐藏 Key、模型数字、Website ID、隐藏 Identifier、隐藏 Token Key、公网接入、Prompt 路径、知识目录、脱敏确认。多行/多库是可选扩展，不伪称总共十次按键。默认客服/欢迎启用、人工按钮启用、1800 秒恢复、自动展开关闭；升级保留原值。

配置闭环为受限候选→校验→历史备份→原子提交→实际组件应用→读回→applied_revision。`configuration_apply/readback/mark_applied` 与 Provider/Prompt/知识接口共同实现，不以保存文件冒充应用。Provider 失败恢复时再次提高 revision，旧请求不能带着相同代次重新发送。普通业务开关不重启容器；Provider 变更需要按组件重建；Prompt/知识通过实际 API 应用。新格式在兼容的 `.yaml` 路径内使用严格 JSON；秘密受限保存，禁止 `source .env`。

## 6. 会话状态、计时与准确边界

状态以 SHA256(website_id + NUL + session_id) 隔离，受限文件位于 `data/runtime/session-<key>.json`。持久 `mode/generation/resume_at/last_human_at/control_watermark/offers/jobs/outgoing` 与全局 revision 分开。待确认 offer 不等于 human；控制事件先持久化，再决定是否发送通知。

仅有效按钮确认与真人公开回复进入 human。自己的每类出站均有 automated/fingerprint 记录，回流先于 REST 响应也能识别；字段缺失时有界回查，失败只取消本次不确定出站，不捏造真人证据。内部 note、在线、正在输入、后台打开不是人工。

正数恢复从最近有效人工事件计算，访客及重复/旧事件不改变；0 永久。到期只回答新问题，不补历史、不发恢复通知。每 5 秒持久扫描，消息/状态/发送前也惰性校验；没有长模型锁。全局关闭保持控制接收，不修改所有会话为人工，重新启用不清空原截止时间。

消息认证/持久化先于成功 HTTP 确认，推理由可恢复任务处理。关键词只消费当前消息并展示非必填 picker，不再为同条调用普通 AI；取消选项消费 offer 但不切人工。确认点击先落盘 human 并递增代次，再发送一次通知；全局关闭时仍记录控制但不发通知。API 错误、未知知识、负反馈、图片失败均不自动转人工。

真实本地已验证：A 展示但仍 AI、点击只暂停 A、B 正常；慢模型期间真人或总开关介入后迟到答案不发；第 6 秒追加人工把 10 秒截止移至至少第 16 秒；n8n 重启后永久状态与 offer 可继续；发送连接中断按 fingerprint 回查仅收到一次。远端已经收到的 POST 无法撤回，不能承诺跨系统绝对零竞态或严格 exactly-once。

## 12. 文档、外部边界与第一次使用

已交付：[安装](../INSTALL.md)、[18 项菜单及子菜单](../MENU.md)、[Crisp 凭据/Hook/SDK](../CRISP.md)、[配置](../CONFIG.md)、[测试](../TESTING.md)、[故障排查](../TROUBLESHOOTING.md)、[安全](../SECURITY.md)、[发布](../RELEASE.md)、[本版说明](../releases/v1.1.0.md)。README 保持简洁；官方协议复核与引用见 CRISP/CONFIG，不把本项目业务动作当作 Crisp 原生字段。

当前没有本轮授权可用的真实 Crisp 测试账户/会话、真实第三方模型 Key、公网 DNS/TLS 或用户站点修改权限；这些逐项为 `External Validation Pending`。本地协议服务不证明真实模型/视觉能力、Crisp 浏览器渲染或官方公网投递。该外部边界不豁免本地菜单/代码/安装门禁。

用已授权 GitHub 浏览器取得两个发布资产，上传目标机同一目录后：

```bash
sha256sum --check SHA256SUMS
tar -xzf ai-support-v1.1.0.tar.gz
cd ai-support-v1.1.0
sudo bash ./install.sh
```

root 执行 `bash ./install.sh`。目标机从包安装不需要 Git/gh，不需预装 Docker/Compose/jq；有现成 gh 授权可按 INSTALL 下载，不使用匿名私有 `curl | bash` 或带 Token URL。之后任意目录运行 `crispai`、`crispai status`、`crispai doctor`、`crispai enable/disable`，单会话恢复用菜单 7。

最小外部动作：填写有效 AI/Crisp 凭据及自己的接入地址；在 Workspace Settings → Advanced configuration → Web Hooks 登记菜单生成的准确生产 URL，订阅 `message:send`、`message:received`、`message:updated`。可选加载/打开欢迎另接一次无密钥 SDK 与 `session:sync:events`。默认 Website 路径不要求两套 Hook；没有可用后台登记权限时不捏造官方 API。用户完成登记后 doctor 继续复核，无需重填十项或重装应用。URL Secret 仅在受控菜单显示，不写入报告。
