## 5. 修改内容与完成功能

- 安装、更新、回滚及相关管理入口统一检查 Docker Compose v2 和 Docker daemon，可在写入新部署目录前清晰拒绝不可用环境。

- 更新在停止 n8n 和 AnythingLLM 前执行容量预检，创建快照时再次检查，避免低磁盘状态先造成服务停机。
- 新增 `SNAPSHOT_MIN_FREE_MB` 和 `SNAPSHOT_RETENTION_COUNT`，默认预留 1024 MiB、保留 10 份有效快照；快照清单记录估算数据和策略。
- 历史裁剪仅删除经过清单校验的受管理快照；回滚安全快照创建期间保护目标快照，避免被数量策略提前清理。
- 人工接管默认关键词增加“真人”，固定提示为“正在为您转接人工客服，请稍候。”；首次消息直接转人工时不再拼接欢迎语。
- 默认 Crisp 标签改为 `ai_resolved`、`knowledge_miss`、`low_confidence`、`human_required`。升级只转换旧项目默认值，自定义标签保持不变。
- 标签读取失败时合并结果为空，workflow 跳过 PATCH 且保留已经生成的回复；读取成功时保留非项目标签并合并新标签。
- 扩充 Markdown、TXT、PDF、DOCX 同步入口、Docker daemon 失败、低磁盘更新拒绝、保留数量、受保护回滚和配置迁移测试。
- `docs/TESTING.md` 增加真实 Docker、Crisp、知识库、图片、更新和回滚的预发布验收步骤。

## 9. 风险说明

- Docker 镜像、n8n CLI、AnythingLLM Developer API 和 Crisp API 的真实版本兼容性仍需在预发布主机确认。
- 快照容量按源数据两倍加预留空间保守估算，但不能覆盖所有文件系统配额、并发写入或异常压缩情形。
- 超过 `SNAPSHOT_RETENTION_COUNT` 的最旧有效快照会永久删除；部署方必须根据恢复点目标调整策略。
- 回滚镜像恢复仍依赖旧镜像 ID 留存在本机；镜像被清理后可能需要重新拉取。
- 标签权限不足不会阻断回复，但该 conversation 将缺少自动标签，需要单独监控 Crisp Token 权限。
- 自动测试中的 PDF/DOCX 只验证部署脚本上传路径，不能证明 AnythingLLM 对具体文件内容解析正确。
