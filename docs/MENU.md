# CrispAI 中文管理菜单

安装完成后，在任意目录执行 `crispai`；普通用户可执行 `sudo crispai`。不必进入源码目录，不需要 alias 或重新登录。`crispai --help`、`crispai --version` 不访问外部 API。也支持 `status`、`doctor`、`init`、`enable`、`disable`、`uninstall`。

首次使用从 [公开仓库新手安装教程](INSTALL.md) 开始，无需 GitHub 登录或下载 Token。下面的 `3 → 10` 表示主菜单 3 后再选子菜单 10，不是要在 Shell 中执行的命令。

宽度至少 80 列的 UTF-8 交互终端显示 Emoji 双栏；窄屏、`TERM=dumb` 或非交互输出降为单栏。`CRISPAI_NO_EMOJI=1 crispai` 使用纯文字。主菜单读取本地事实，不自动发付费模型请求。显示“待验证”不代表已连接客户。

## 操作约定

所有子菜单 `0` 返回；非法数字重新提示。空输入按提示保留或取消，不表示同意危险操作。EOF 退出；Ctrl+C 中断未确认输入，已生效配置保留。需要确认时只输入数字 `1` 或 `0`。程序明确提示失败或待生效时，不要把文件已经写入理解为运行成功。

多行正文：逐行粘贴，单独一行 `::END::` 保存，`::CANCEL::` 放弃；正文需要这两个字面量时写 `\::END::` 或 `\::CANCEL::`。中文、空行、Emoji、引号、反斜线、`$` 是数据，不会作为命令执行。空正文不覆盖旧 Prompt。

受管目录下的 `config` 为权威业务配置，密钥仅在受限 `.env`；候选文件先校验再原子保存、应用与回读。`runtime.yaml` 的 `revision` 和 `applied_revision` 一致才表示该代配置已确认应用。常规选项不要直接修改 AnythingLLM/n8n Web UI，否则可能与 Shell 配置偏离；选项 16 的重新同步可恢复受管配置。

## 1. 快速初始化

未安装直接进入十项向导；已安装显示 `1 保留现有配置继续检查与修复 / 2 重新运行十项初始化（保留数据）/ 0 返回`。默认不会清空知识或重生密钥。普通文件路径流程为十项主要输入，确认后零次内部参数必答；粘贴及多库编辑是相应步骤内的自选输入。[安装手册](INSTALL.md)列出全部步骤。

新装默认：客服启用、人工关键词确认按钮启用、恢复 1800 秒、欢迎启用、自动展开关闭。升级保留已有合法设置。示例：中断后运行 `crispai init` 续装，不重新创建数据库。安装可能拉镜像、启动服务和下载本地 Embedding；外部凭据错误只修对应项。

## 2. 状态与自检

子菜单：`1 快速自检：本地组件与配置状态 / 2 完整自检：外部连接与少量模型测试 / 3 查看上次自检结果（缓存）/ 4 修复本次发现的可自动修复问题 / 5 导出脱敏自检报告 / 0 返回`。

`1` 等价于 `crispai doctor --local`，检查当前依赖、Docker/Compose、每个应启用容器、数据库应用认证、AnythingLLM Key/Prompt/知识对账、n8n 生产 Code、Provider 适配器和持久任务状态，不访问外部业务服务。默认 `crispai doctor` 另对已配置的 Crisp/公网入口做有界只读检查；不执行模型推理。

`2` 等价于 `crispai doctor --full`，增加少量合成模型调用，可能计费；不会向客户发送消息。`3` 明确显示上次结果的时间与缓存标识。`4` 等价于 `--fix`，先列出计划，只补确实缺失的受支持依赖、启动本项目已停止服务、修复受管入口/权限，然后重新检查；不会更换业务 Key、重置数据库、删库或解除人工。需要完整恢复时仍去选项 13。

`5` 把结构化白名单结果导出到受限 `logs/doctor-时间-进程号.json`。命令 `crispai doctor --json` 的 stdout 只有 JSON，可组合 `--local` 或 `--full`；普通输出和缓存文件包含检测时间、范围、耗时、观察摘要及修复建议。默认总预算 90 秒，可用 `--timeout 120` 调整到 1～600 秒；显式修复单独获得有限维护预算。

退出码：`0` 本范围无警告/故障；`2` 有警告或待接入；`1` 有故障；`64` 参数错误；`130` 中断。菜单会展示非零结果并允许返回。安装/升级按本地关键故障决定失败，外部待接入不会被机械当作必须重装。`PASS` 仅代表本次该项有证据，`WARN` 表示待接入/处理中/不确定，`FAIL` 表示明确故障，`SKIP` 说明本次不适用或因上游不可用未检查。

示例：登记 Hook 后选 `2`，检查当前凭据绑定的接收事实；数据库认证失败则按建议核对成套恢复，不能只凭容器 running 判正常。客服主动停用、欢迎关闭、0 秒永久人工和合法外部反代均为业务状态，不会被自检改成另一种设置。

## 3. 第三方 AI 接口

子菜单：`1 查看脱敏配置 / 2 修改 API 地址 / 3 替换 API Key / 4 刷新并选择模型 / 5 手动指定模型 / 6 选择请求协议 / 7 测试当前模型 / 8 测试图片能力 / 9 自定义请求头 / 10 同时更换供应商地址、Key 与模型 / 0 返回`。

地址接受根 URL、已有 `/v1` 和合法代理前缀。Key 隐藏输入；空值保留。模型列表支持数字、`n`/`p` 翻页、`/词` 搜索；404/空列表可手填，401/403 应先修凭据。协议 `1 Chat Completions / 2 Responses` 必须通过最终容器调用；支持 Responses-only 的最小适配器由安装器部署。自定义头隐藏值，输入 `::DELETE::` 删除指定头；Host 等受管协议头不能覆盖。

保存会验证少量合成请求，可能计费；不扫描全部模型。`.env` 保存秘密，`config/provider.yaml` 保存非敏感设置。应用按需要重建 Provider 适配器、AnythingLLM 和 n8n，短暂影响服务，但不重置人工状态。实际容器验证失败恢复旧值。

示例：同供应商换 Key：`3 → 3 → 粘贴新 Key → 1`；再选 `4` 从远端列表选模型、`7` 测试。换不同供应商用 `3 → 10`，把地址、Key、协议和新模型作为一份候选一起验证，避免旧模型挡住新地址保存。

## 4. 客服提示词

子菜单：`1 查看当前 Prompt 与状态 / 2 直接粘贴多行正文 / 3 从文件导入 / 4 终端编辑候选正文 / 5 恢复上一版 / 6 导出当前 Prompt / 7 合成问题验证 / 0 返回`。

正文保存到 `config/prompt.md`，历史在 `backups/config-history`。文件路径可含中文和空格，须为普通可读文件；不支持符号链接。编辑器只在现成 nano/vi 可用时使用，否则粘贴即可，不要求另装。Prompt 上限 256 KiB，导出不覆盖已有目标。

示例：`4 → 2`，粘贴“优先依据当前知识回答；不知道时简短追问。”，输入 `::END::`、`1`，再选 `7` 输入虚构问题。保存后核对 AnythingLLM Prompt 和 n8n 可读正文；同一旧 conversation 的下一问使用新 Prompt，无需新建聊天或重启全栈。同步失败恢复上一版；自定义 Prompt 不能取消鉴权、总开关或人工控制。

## 5. 多知识库管理

子菜单：`1 查看知识库及索引状态 / 2 创建命名知识库 / 3 重命名知识库 / 4 粘贴知识正文 / 5 导入文件或目录 / 6 查看/删除指定条目 / 7 启用知识库 / 8 停用知识库 / 9 删除知识库 / 10 同步知识库 / 11 重建索引 / 12 检索问题预览 / 0 返回`。

`2` 输入名称生成稳定库 ID；`4` 数字选库、输入条目名、粘贴多行正文；`5` 选库后输入 MD/TXT/PDF/DOCX 文件或目录。支持中文、空格与大写扩展名。单文件须非空且不超过 50 MiB；目录需普通文件。`6` 先选库再数字选条目，确认后删除；`9` 删除库需确认。`10～12` 可选全部启用库或单库。重建会重新索引并增加计算与下载耗时，普通更新优先增量同步。

`knowledge/catalog.json` 记录名称、ID、启用状态、文档与版本；`knowledge/kb_*/sources` 保存原文；manifest 与 workspace 文档映射用于真实对账。库启用后共同服务于一个客服 workspace，客户上下文不被拆散。同库同名文件用于更新同一条目；跨库同名文件独立。同内容在不同库按独立归属管理，删除一库不误删另一库。

停用保留原文但从新检索移除；删除移除当前库定义和原文，恢复副本仍可能在受限配置历史或备份中。索引尚在处理时显示 pending/错误原因；不要反复删库，选同步继续对账。失败保留或恢复旧有效版本。历史聊天里已出现的旧事实不会因此自动抹除，政策变动应在新 Prompt 中明确以当前知识为准。

示例：用 `5 → 2` 分别建立“订阅使用”“电脑排障”“手机排障”；各用 `4` 粘贴虚构事实，`12` 用中文改写问题检索。再用 `8` 选“电脑排障”，核对列表状态及检索来源；其他两库应不变。不把上传成功或模拟模型固定回答当作真实语义检索证据。

## 6. 关键词与按钮

子菜单：`1 查看规则 / 2 创建规则 / 3 修改规则 / 4 启用规则 / 5 停用规则 / 6 删除规则 / 7 输入客户文字预演 / 0 返回`。

规则编辑包含名称、关键词（英文逗号分隔或 `::PASTE::` 逐行）、排除词（`::CLEAR::` 清空）、包含/完全匹配、动作、优先级、冷却秒数、按钮有效期、正文及按钮/确认文案。优先级越大越先；同优先级按稳定规则排序。动作是人工确认按钮、固定回复、多级菜单或知识问答。人工按钮默认冷却 60 秒、有效期 600 秒。

示例：`6 → 3` 选择人工确认规则，词表 `人工,转人工,人工客服`，包含匹配，保留“不要人工”等排除词，按钮填“召唤人工客服”，保存；再用 `7` 预演“我想转人工”和“不要人工”。预演不发真实消息。

`config/keyword.yaml` 被工作流逐次读取，保存无需重启。命中仅发送真正 picker，消费本条关键词消息、不再附加一份普通 AI 答案；未点击而继续提问仍由 AI 服务。点击有效按钮才暂停当前 conversation；“继续 AI 客服”不暂停。文本冒充按钮、跨会话、重复及过期点击无权接管。旧直接 handoff 规则在升级时迁移为确认按钮。

## 7. 人工接管与恢复

子菜单：`1 查看恢复设置 / 2 修改恢复秒数 / 3 查看当前人工会话 / 4 手动恢复指定会话 / 5 调整指定会话倒计时 / 0 返回`。

`handoff.resume_after_seconds` 位于 `config/handoff.yaml`。新装 1800，范围 0～604800 秒；`0` 是不自动恢复，不是立即恢复。正整数从首次有效确认按钮或最近一次新的真人公开回复计时；访客消息、机器人确认、重复/乱序旧事件不重置。设置默认值只影响之后的接管/真人新回复，现有截止时间保留；`5` 明确选中某会话才从现在重新计时。

示例：`7 → 2 → 300` 设五分钟；`3` 看原因与剩余时间；`4` 按数字选 A、确认恢复，不影响 B。A 在 t0 由真人回复，t6 再回复且设 10 秒，则 t16 前不恢复；到期仅回答下一条新问题，不补答旧消息，也不发恢复通知。5 秒持久扫描并结合消息到达时校验，重启不丢截止时间。

永久人工状态不会随普通去重缓存清理。v1.0.1 旧状态只保存 session 哈希，首次该会话再来事件时惰性迁移并保留人工；尚未再来事件的旧哈希不能在菜单中凭空还原出会话名称。真实人工公开文件/图片也接管，内部 note、在线、已读、打开后台不接管。

## 8. 客服总开关

子菜单：`1 启用自动客服 / 2 停用自动客服 / 3 查看当前状态 / 0 返回`；等价命令 `crispai enable` / `crispai disable`。

修改 `config/runtime.yaml` 并使旧任务代次失效，不重启容器。关闭时 AI、规则、欢迎、反馈追问和普通错误提示均静默，Hook 鉴权和真人状态记录仍运行。重新打开保留 A 的人工期限，B 可继续 AI，不补答停用期间历史。

总开关不等于停止容器、不等于所有会话转人工、不隐藏 Crisp 聊天框、不影响真人。维护停机见选项 16。

## 9. 欢迎语与多级菜单

子菜单：`1 查看欢迎配置 / 2 启用欢迎 / 3 关闭欢迎 / 4 粘贴多行欢迎文案 / 5 选择触发方式 / 6 设置自动展开聊天框 / 7 设置欢迎附带根菜单 / 8 多级菜单管理 / 9 查看无密钥页面接入片段 / 0 返回`。

欢迎保存在 `config/menu.yaml`，新装启用、`first_message`、自动展开关闭。文案可多行，最多 10000 字符；启停/正文保存后下一次符合条件的新会话使用新值，不重启容器。同一会话欢迎持久去重，不因刷新、多个标签页或重启重复；人工期间及全局关闭不欢迎。只关欢迎不关 AI 主回复。

`5` 选 `1 首条访客消息 / 2 页面加载 / 3 访客打开聊天框`。后两项及自动展开需要把 `9` 的无密钥片段接入网页一次，详情见 [CRISP](CRISP.md)。发送欢迎不等于浏览器展开；自动展开使用官方 `chat:open`。配置获取失败时不强制展开。

`8` 的菜单树子菜单为 `1 查看/预览 / 2 新建节点 / 3 修改标题 / 4 新增/修改按钮 / 5 删除按钮 / 6 删除节点 / 7 设置根菜单 / 0 返回`。新建选父级自动建立导航；按钮输入数字、标题、动作及排序。支持下级菜单、固定回复、知识问答、人工确认、返回父级；下级环、无效引用和超过十层深度会被拒绝。删除节点前先移除引用。

示例：`9 → 4` 粘贴“您好，请说明遇到的问题。”、保存；`2` 启用、`3` 关闭分别验证。用 `8 → 2` 建“电脑标准排障”等节点，问答内容从自己的知识库取得，不将示例当成经营承诺。

## 10. Crisp 接入设置

子菜单：`1 查看脱敏配置 / 2 修改 Website ID / 3 修改 Token Identifier / 4 修改 Token Key / 5 修改域名/公网地址 / 6 测试 REST 与公网接入 / 7 受控显示真实 Hook URL / 8 轮换 Website Hook Secret / 9 高级 Token/Hook 模式 / 10 接入教程 / 11 同时更换 Website 与整组 Token / 12 查看 Hook/真实会话接收事实 / 0 返回`。

Identifier/Key 隐藏输入，空值保留；`.env` 受限保存。保存验证格式/实际接入并按需更新 n8n/反代；错误只修相应项。换网站或轮换整对 Token 用 `11` 将新值一并验证，避免新 Identifier 配旧 Key。Token tier 和 Hook mode 是两个独立选择。`7` 显示含 Secret 的地址前有确认，禁止截图、公开日志和把 URL 放网页。`8` 会使旧地址失效，必须同步后台 Hook。`12` 显示与当前凭据绑定的收件/实际往返事实，协议服务不会冒充真实 Crisp。详细步骤见 [CRISP](CRISP.md)。

## 11. 命中率与回答反馈

子菜单：`1 知识命中分析 / 2 回答反馈统计 / 3 查看标签配置 / 4 修改标签 / 5 反馈启停与保留设置 / 6 清除统计与反馈记录 / 0 返回`。

统计读取 `data/analytics/events.jsonl` 及受限轮转文件，规则位于 `config/tags.yaml`、`config/feedback.yaml`；保存后工作流直接使用。`4` 可改已回复/未命中/低置信度/人工标签或启停标签；只并集合并，不抹外部标签。标签失败不阻断正文。“已回复”不等于 Crisp resolved。

`5` 可启停反馈、设置有效期秒数（1～604800）或保留天数（默认 30，1～3650）；`6` 二次确认后清除受管统计与待反馈摘要，保留人工模式。命中率只以可观察的知识查询为分母；元数据缺失是未知。反馈覆盖率与有效好评率分开，无反馈显示暂无数据。负反馈不转人工。示例：先看 `1` 的命中/未命中/未知，再判断是否需要补知识，不依据模型 confidence 伪造命中。

## 12. 配置导入导出

子菜单：`1 导出完整业务配置与知识原文（不含秘密）/ 2 预览/导入迁移包 / 0 返回`。

导出使用绝对 `.tar.gz` 路径，默认 `backups/business-config.tar.gz`。包含 Prompt、各库原文/元数据、规则/菜单/欢迎/开关/恢复/反馈/标签、Provider 非敏感配置；不含 Key、Token、自定义秘密头、客户会话和内部密码。知识即使无 Token 仍敏感。导出目标同名时会替换，重要旧包使用不同文件名。

示例：导出 `/opt/crisp-ai/backups/move-demo.tar.gz`，新实例先通过初始化准备自己的凭据，再选 `12 → 2` 输入包路径。先展示预览，再数字确认替换业务配置；本机秘密不被空模板覆盖。完整性、路径、链接、schema 和大小校验失败不导入；应用失败恢复本机旧配置并提示自检。上限为压缩 128 MiB、展开 512 MiB，超限会拒绝，不声称无限包容量。

## 13. 备份与恢复

子菜单：`1 创建本机完整备份 / 2 列出备份 / 3 恢复完整备份 / 4 容量与版本保留策略 / 5 设置版本快照保留数量 / 0 返回`。

完整备份与选项 12 不同：包含 `.env`、数据库、AnythingLLM、n8n、Prompt/知识和持久人工状态，必须受限保存，不得上传 GitHub。创建/恢复会进入维护锁，并为一致性短暂停止有关应用；恢复按快照重建绑定目录的容器。缺磁盘、备份失败或历史镜像不可用必须先修复，不能认为副本已安全生成。

`5` 的数量 `0` 表示不自动清理版本快照；只作用后续创建快照。示例：创建带日期的完整包，校验保存路径后再进行升级。恢复需明确数字确认并保留安全快照，详细命令见 [INSTALL](INSTALL.md)。

## 14. 更新与回滚

子菜单：`1 匿名在线更新至最新正式版 / 2 从已解压的新版本目录离线升级 / 3 从原 Git 源码更新（高级） / 4 查看历史快照 / 5 回滚指定快照 / 0 返回`。

推荐选择 `1`，再输入 `1` 明确确认。它调用受管部署内的 `get.sh --update`，匿名解析公开仓库当前 Latest，先锁定一个正式 tag，再下载该 tag 的完整包与 `SHA256SUMS`；只有 Release 状态、唯一资产、校验和与安全归档检查全部通过后才调用原有更新器。无需 Git、`gh`、GitHub 登录、浏览器下载或手工解压；已经是最新版时不改动实例。更新前仍由更新器创建一致性快照，失败自动回滚。

`2` 是已有可信离线包时的高级入口，输入完整解压目录；`3` 只适用于部署标记记录的原 Git 工作区仍可访问的维护环境，不建议普通用户直接跟随 `main`。`4` 查看历史快照；`5` 输入列表中的快照 ID，再数字确认恢复。维护期间不能接待新消息，完成后用 `crispai doctor` 检查。旧人工状态、秘密、Prompt/知识按迁移与快照规则保留，已发旧按钮可能因代次变化失效；在线检查或下载失败不会覆盖当前实例。

## 18. 卸载系统

子菜单：`1 安全卸载：移除本项目服务，保留配置和数据 / 2 完整清理：移除本实例服务及数据，先创建外部备份 / 0 返回`。两个入口与 `crispai uninstall` / `uninstall.sh` 共用实现。
