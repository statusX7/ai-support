## 5. 修改内容

- 修复安全卸载的真实 Docker 边界：`docker compose down` 后按 Compose 项目标签再次查询全部容器与网络。
- 外部 Provider 容器仍占用项目网络时，卸载会保留程序、配置、数据和自动备份，返回非零并说明占用原因；不会强制删除外部容器。
- 安全卸载后的同路径重装会先校验保留 `.env` 的 `0600` 权限、必需字段、端口、URL、枚举、Crisp Auth 一致性、Provider 一致性和业务配置结构。
- 保留配置有效时直接复用，不要求重新传入 Provider 或 Crisp 环境变量；缺失、占位、损坏或不一致时保持卸载状态并要求显式 `--reconfigure`。
- 外部 E2E 的文本、上下文和转人工断言改为只检查本轮新增后的最新 AI 回复，旧历史消息不能造成假阳性。
- 图片外部 E2E 新增 `AI_SUPPORT_E2E_IMAGE_EXPECTED_FACT`，最新回复必须包含测试图片中的唯一事实，并排除 URL 校验、视觉不支持和 Provider 失败提示。
- 扩展安全卸载、残留网络、保留配置校验、同路径恢复的自动回归，并同步安装、安全和测试文档。
