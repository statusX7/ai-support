# 安全边界与敏感数据

本项目源码仓库公开，部署实例仍是由管理员自行掌控的单实例客服，不是可让不可信人员共用的执行平台。CrispAI 管理权限、Docker 权限、n8n 管理权限均应只给可信管理员。Prompt/知识/模型输出不具备授权能力，不能改变系统级开关、Webhook 鉴权或人工状态。

## 公开仓库不等于公开部署数据

任何人都可阅读 Git 历史、Issues 和 Release 资产。正常下载无需 GitHub Token；不要在下载 URL、公开问题或截图中附加认证值。[新手教程](INSTALL.md) 的一行命令通过 HTTPS 完整取得 get.sh，校验语法与完整结束标记后运行；它锁定正式 tag 并下载同版完整包与 `SHA256SUMS`，校验失败停止。原始入口信任 GitHub 上的本仓库及 HTTPS；结束标记不是密码学签名。包的 SHA256 证明与所取清单一致，也不是独立的发布者签名。

获取器禁用 curl/wget 用户配置、netrc、Cookie 和 Authorization，临时文件随机创建且受限；不回退 main 源码、不从 HTTP/不明镜像下载生产包。解压前拒绝路径穿越、重复路径、链接、特殊文件和异常容量。推荐命令可能以 root/sudo 安装缺失的 CA/curl，完整包继续自动安装运行依赖。

普通 `doctor` 只读业务状态，允许保存自己的脱敏诊断缓存；`--local` 无外部业务请求，`--full` 才发少量合成推理。`--fix` 限于列出的受管依赖/入口/权限/停止服务，不改业务 Key、客服开关、人工截止时间或知识内容。JSON 和导出只保留白名单摘要，不输出完整 inspect/env、Prompt、知识或客户标识。

反馈问题只提供版本、系统、复现步骤与脱敏错误。即使 Prompt、知识或业务导出不含 Key，也可能包含私人业务内容，不能作为公开附件。若秘密已经泄露，先撤销/轮换再处理传播副本；只删除当前文件或关闭 Issue 不能让凭据重新安全。

## 密钥、日志和文件

- `.env`、向导恢复 JSON、候选认证文件和完整备份受限保存；Key 不进入 Git、Release、普通日志、shell history 或公开 URL。输入 Key 隐藏，空输入保留旧值。
- `.env` 严格解析，不 `source` 或 `eval`；请求授权头经受限临时文件/进程内部读取，避免把密钥直接放命令参数。禁止生产 `set -x`、打印整份环境或完整展开 Compose。
- API Key、Crisp Identifier/Key、Website URL Secret 和 Plugin Signing Secret用途不同；URL Secret 只在明确确认后的本机终端显示，不写网页片段。反代不得记录敏感查询串。
- n8n/AnythingLLM 受管数据按运行 UID/GID 授权；程序/业务配置只给必要读取权限，不 chmod 777。Prompt/知识是敏感业务资料，即便包内没有 Token 也不能公开。
- 菜单日志替换已知秘密，但不能保证任意供应商错误消息或业务正文都可公开；导出的诊断文件只包含白名单事实。转发前仍需人工复核。

## 网络与应用暴露面

n8n/AnythingLLM 管理端默认绑定宿主回环，PostgreSQL 和 Provider 适配器只在项目网络；受管 Caddy 仅允许生产 Hook 与无密钥的 SDK/UI 配置路由，其余返回 404。网页只读 enabled/welcome/auto_open/trigger/revision 等白名单字段，不提供管理操作、Prompt、知识或凭据。

自动 HTTPS 不抢占已有 Nginx/宝塔/Caddy，也不修改无关站点、防火墙或 SSH。已有反代片段需有权管理员合入。Docker 端口发布会影响宿主暴露面，不应只看 ufw 表象；检查实际监听与公网可达性。安装器使用官方仓库/签名/TLS，不使用 `curl -k`、全系统升级或不校验的远端脚本替代可靠安装。

Docker Engine/socket 权限本身等同高权限；拒绝把远程 daemon 用于本机 bind mount。自动安装 Docker 不代表项目拥有全部宿主容器数据；卸载不移除 Docker、containerd 或全局软件包，不全局 prune。

## Hook、控制状态与消息可靠性

Website Hook 验证独立随机 URL Secret 与目标网站/会话。Plugin Hook必须验证原始 body、签名和五分钟时间窗，不因校验失败降级。两模式均限制载荷，事件去重区分 picker 更新；SDK信号只有经 Crisp Hook 才能触发当前会话受控欢迎，不接受匿名请求向其他会话发消息。

人工按钮需已登记 offer、website/session、fingerprint、choice、有效期和代次，原子消费一次。所有本项目出站统一标 automated 并预登记 fingerprint；不靠昵称或相同正文猜机器人，歧义事件有界回查，无法确认就抑制当前发送而不伪造人工证据。

确认 HTTP 成功前保存受限恢复任务。短事务控制会话，耗时模型请求不持锁；全局或人工控制使旧 generation/revision 失效。普通队列、控制事件和会话状态分离，永久人工不能随缓存清理失效。收到并确认真人控制后，尚未发出的旧结果不会继续发送；已到达 Crisp 的 POST 无法追溯撤回。发送超时先对账，有限重试，不承诺跨系统严格 exactly-once。

网站 Hook 的第三方投递策略不是本项目可控制的永久消息队列，维护停机时不能保证补回根本没收到的事件。需要让机器人静默但继续记录真人状态时用客服总开关，不停止容器。

## 图片、上下文与 Prompt Injection

图片仅接受 HTTPS、允许的 Crisp 主机或管理员明确列出的精确主机；拒绝用户信息 URL、异常端口、DNS 指向私网/回环/元数据。解析 DNS 后将已批准地址固定到下载连接，防重绑定；不跟随跨主机跳转，不传供应商授权头给文件主机。

下载限制 8 MiB、10 秒，检查实际格式与 MIME；支持的格式为 PNG/JPEG/WebP/GIF，已解析的尺寸必须满足像素上限。图像/文本本身仍为不可信资料，不能执行其中的 Shell 或“忽略规则”指令。模型不支持或图片失效时要求文字补充，不自动转人工。

上下文按网站+conversation 隔离，只采用公开访客/AI/真人历史，排除内部 note 和控制卡片，有限截断。AnythingLLM session 使用显式 reset，避免再叠加重复内部历史；最新 Prompt/启用知识用于后续问题。删索引不抹历史对话里已出现事实，不能把知识删除描述为全面擦除。

为避免下一问丢失未在公开答案复述的图片细节，成功的视觉解析另在该会话 0600 状态中限时保留：最多 3 份、每份 2000 字符、24 小时。这里只保存受限解析及内部关联标识，不保存图片 URL 或原始字节；仅在近期 20 条公开历史中找到对应附件时加入上下文，仍受总上下文长度限制，并标注为不可信客户资料。到期由正常会话处理/扫描裁剪，不影响永久人工状态；重启不扩大期限。人工/总开关使请求代次失效时，迟到解析不保存。摘要可能含客户资料，随完整本机备份保护，不进入诊断或业务配置迁移包。

默认统计不留明文问题；必要诊断摘要限长脱敏，保存期限和清理入口应按实际用途设置。原始消息仅为未完成任务恢复受限保留，完成后删除任务正文和计划；运行状态及本机快照依然可能含会话资料。

## 备份、迁移与归档

选项 12 的业务迁移包包含知识原文和配置，不含秘密、数据库或客户聊天。新实例必须自行提供有效凭据；导入保留本机秘密，不能把空模板覆盖 Key。拒绝重复路径、穿越、符号/硬链接、特殊文件、超量内容和损坏校验/schema；不执行包中脚本。

选项 13 的完整本机备份和 v3 版本快照包含 `.env`、数据库、n8n 加密凭据、AnythingLLM、知识及人工控制状态，必须按含秘密的资产保管。只恢复自己信任的备份，保证历史镜像可用；SHA 校验只证完整性，不替代来源信任。旧 v2 快照不含 `.env`，不能夸称完整灾难恢复。

备份时暂停相关应用取得一致数据；回滚校验归档和镜像后恢复，并重建绑定目录的容器，避免旧 inode。失败保留安全恢复点并报错，不把 marker 改 ready 掩盖故障。快照按数量清理会永久移除旧恢复点，默认 10，0 不自动清理；离线副本和磁盘监控仍由管理员负责。

## 卸载与全局命令所有权

安全卸载保留 `.env/config/knowledge/data/backups/logs`，删除本项目服务与程序、自己拥有且指向当前实例的 `crispai`。完整清理需数字双确认，先在删除目录之外生成含秘密的完整备份；备份失败不得继续。校验绝对规范路径、实例 marker、Compose标签及残留资源，拒绝根目录、符号链接逃逸或无法证明的目标。

外来同名命令不能静默覆盖；管理员主动选择备份替换时显示可恢复路径。卸载不删除他人的同名命令，也不停止其他容器或网站。外部容器占用项目网络时中止清理并提示，不能因 Compose 返回 0 就假称资源全无。

## 发布前安全检查

运行 `bash tests/test_static_security.sh`、归档安全测试、`git diff --check`，扫描当前内容、非忽略新文件、完整 Git 历史、归档与受限转录。扫描不能证明不存在所有形式的秘密：不把真实账号、用户知识或测试会话加入 fixture，发布只使用固定清单。若确认秘密曾泄露，必须先轮换并按授权处理历史，而不是只删当前文件。详细门禁见 [RELEASE](RELEASE.md)。
