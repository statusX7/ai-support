## 2. 结论

v1.0.1 修复了 v1.0.0 将依赖检查、业务配置和应用初始化分散在安装入口中的问题。正常首次安装入口现在是：

```bash
sudo bash ./install.sh
```

脚本会先用 Bash 和发行版包管理器补齐最小工具，随后执行十项中文快速初始化；用户确认后，自动安装或复用 Docker Engine、CLI、containerd 与 Compose，启动 daemon，运行测试容器，生成内部密钥，启动 PostgreSQL、AnythingLLM、n8n，创建 AnythingLLM Developer API Key 与 workspace，同步 Prompt 和知识索引，导入并发布生产 workflow，最后按事实写入 `ready` 或 `local-ready`。

本地安装完成与外部 Crisp 接入分开记录。没有真实 Crisp 凭据、公网 DNS 或 Hook 登记权限时，不销毁本地部署，也不宣称已经开始接待客户。

## 4. 修复前后调用链

### v1.0.0 实际链路

```text
install.sh
→ source common.sh
→ 参数解析
→ 询问部署目录
→ require curl/jq/openssl/...（缺少即退出）
→ require Docker/Compose/daemon（缺少即退出）
→ 分散询问 n8n、Webhook、Crisp、AnythingLLM、Provider
→ 创建配置和容器
→ 局部初始化
→ 无条件 state=ready
```

### v1.0.1 实际链路

```text
install.sh
→ 无运行级副作用地 source bootstrap/common/wizard
→ 先处理 --help/--version/参数错误
→ root 或 sudo 受控提权
→ bootstrap_prepare_minimal_dependencies
→ 识别 new / collecting / installing / local-ready / ready / uninstalled-data-kept
→ 首次安装自动进入 quick_init_wizard
→ 十项脱敏确认
→ bootstrap_prepare_docker_runtime
→ 生成或复用内部密钥并原子写配置
→ docker compose config/up 与真实健康等待
→ AnythingLLM API Key/workspace/Prompt/知识索引
→ n8n import/publish/restart/生产 webhook Code node 检查
→ 应用健康检查和首次无密钥备份
→ Crisp REST 与公网 Hook 分层检查
→ ready 或 local-ready 完成页
```

引导模块和向导模块被 source 时只定义函数，不检查 root、不读取完整配置、不调用 jq/Docker，也不改变调用者的 Shell options。

## 13. External Validation Pending

以下三类外部资源本轮没有提供，均未计为通过：

1. 真实 Crisp Website/Token 对 REST conversation、message、meta/tag 的权限，以及后台 Website Hook 登记。
2. Crisp 公网 HTTPS 实际投递到 n8n，再经 AnythingLLM 与真实第三方 OpenAI Compatible Provider 回写 Crisp 的完整 conversation。
3. 真实第三方模型的语义回答和视觉图片识别，以及用户掌握域名的 DNS、证书和外网可达性。

本轮使用的 Provider 是隔离协议服务，只证明 `/models`、Chat Completions、Responses、视觉请求结构、错误分支和容器网络接线；不声称它是真实模型。Crisp 使用格式有效但无权限的虚构凭据，实际得到 401，并正确落为 `local-ready`。

用户需要完成的最小外部动作：准备有效 AI/Crisp 凭据；若脚本不能通过官方权限自动登记 Website Hook，在 Crisp 后台将完成页给出的生产 URL 登记为 Hook，并订阅 `message:send` 与 `message:received`；域名模式还需用户控制 DNS 并允许 80/443，已有反代模式按生成片段接入。数据库、内部密码、AnythingLLM Key/workspace、n8n workflow 和普通依赖不再要求手工配置。

## 14. 已知限制与风险

- 本轮真实空机系统只有 Debian 12 amd64；Debian 13、Ubuntu 22.04/24.04 以及 arm64 没有真实整机结果，不能从分支桩测试扩大宣称。
- QEMU TCG 是依赖引导隔离证据，不是本地应用通过证据。AnythingLLM 固定镜像的 Prisma 原生组件在本机 TCG 的 `qemu64`、`max`、`Haswell-v4` 下均出现过 `Illegal instruction` 或 139；这些运行没有计为通过。真实 CPU Debian 12 主机上的同一固定镜像全新安装、重建、重启、升级和回滚均保持健康且重启计数为 0。
- 安装器的健康等待有明确上限，但首次下载本地 Embedding 模型和首次拉取镜像的耗时仍取决于 CPU、磁盘与网络；目标虚拟化平台需要提供固定镜像支持的 CPU 能力。
- AnythingLLM 数据和版本快照可能包含知识、会话或业务配置；备份虽排除 `.env` Secret，仍必须按敏感业务数据保护。
- n8n、AnythingLLM 和 PostgreSQL 默认不直接暴露公网；完整 URL/现有反代分支的外部服务器配置仍由其管理员控制，安装器不会停止或覆盖现有网站。
- private GitHub 仓库的 clone/download 需要合法访问权限；Release 包本身解压后不需要 GitHub CLI。
