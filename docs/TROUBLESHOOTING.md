# 故障排查

先运行 `crispai status` 查看已有事实；需要实际探测时运行 `crispai doctor`。普通修复从相应菜单完成，不重填十项、不删除数据库、不重生全部密钥。`local-ready` 是本地已完成、外部接入仍待验证，不是 AI 已接待客户。

## 安装、依赖与命令

| 现象 | 核对与修复 |
| --- | --- |
| `crispai` 找不到或坏链接 | 程序完整时运行 `sudo bash /opt/crisp-ai/manage.sh`，选 `16 → 7`；自定义目录替换路径。管理入口也不可达时按[高级维护](ADVANCED.md)安全取得独立 get.sh，使用 `--repair` 校验同版正式包后修复受管命令。安全卸载后重跑[安装命令](INSTALL.md)恢复保留资料。 |
| `crisp` 找不到，但 `crispai` 正常 | 正式命令是 `crispai`；v1.2.0 在无外来同名命令时登记兼容 `crisp`，两者共用管理器。仍需自检组件和真实回复，不能把全部客服故障归咎拼写。 |
| 同名命令被占用 | 安装器不静默覆盖。数字选择保留并取消，或明确备份原命令后安装；显示的备份可恢复。不要手动删未知文件。 |
| 无 root/sudo | 用拥有部署管理权限的账号运行；平台禁止提权是权限边界，不能伪称依赖已装。帮助和版本仍可读。 |
| jq/Compose 缺失、daemon 停止 | `crispai doctor --fix` 或 `16 → 5` 自动修复；未安装时重跑在线安装命令。默认自检只报告缺失项，显式修复才安装依赖。 |
| apt 锁/下载超时 | 等待脚本的有限重试及具体错误，确认仓库网络后同命令续跑。不要删包管理 lock、杀其他 apt 进程、关闭 TLS 校验或替换全部软件源。 |
| Ctrl+C/EOF | 未确认输入不会覆盖有效配置；重跑 `crispai init` 或原安装命令继续。查看安装阶段，勿把中断当成功。 |
| 镜像/Embedding 下载慢 | 检查目标系统架构、磁盘、内存和允许访问的镜像/模型源；首次下载较慢。索引 pending 先重试同步对账，不删除仍处理中文件。 |
| 非 systemd/衍生发行版被拒绝 | 查看 [INSTALL](INSTALL.md) 支持等级；不改发行版 ID 或假装成受支持系统。 |
| 双栏错位或终端不支持 Emoji | 使用 UTF-8；窄屏会单栏。可用 `CRISPAI_NO_EMOJI=1 crispai`；`TERM=dumb` 无控制动画。 |

## 在线安装与公开下载

| 现象 | 核对与修复 |
| --- | --- |
| 下载时认为需要 GitHub Token | 仓库、入口和正式资产可匿名读取。原样执行 [新手教程](INSTALL.md) 唯一推荐命令，不需要 gh/Git/PAT；不要把业务秘密附给 GitHub 下载。 |
| Release 资产 404/403/429 | get.sh 会锁定具体正式 tag，并有限重试。检查 GitHub 网络或匿名限流；稍后重跑同一命令。不会回退安装 main 或忽略缺失资产。 |
| 缺少 curl 或 CA | 推荐命令先复用可用的安全 curl/wget；两者不可用或 CA 缺失时，在 Debian/Ubuntu 通过 root/sudo 自动补齐。无法提权时使用有 sudo 权限的账号运行。 |
| TLS/DNS/连接超时 | 核对系统时间和服务器访问 GitHub/raw/资产主机的网络；保留 HTTPS 证书验证。不要添加 `-k`、改 HTTP 或把 Token 作为网络修复手段。 |
| SHA256 不匹配、HTML 或截断包 | 引导器在执行安装器前拒绝，临时包会清理；现有配置保留。重新运行原命令重新取得同版资产，不手工修改 SHA256SUMS。 |
| 需要交互终端或输入直接 EOF | 在正常 SSH 终端运行推荐命令；代码先完整保存到随机临时文件，再调用安装器。不要用 `curl | bash`、进程替换或把业务答案作为脚本 stdin。 |
| 相对 Prompt/知识路径找不到 | 路径相对执行在线命令时的目录，不是内部解压目录；确认文件可读且不是符号链接，也可在向导直接粘贴。 |
| 目标目录非本项目/目标版本更低 | 入口会拒绝写入。选择正确 `--deploy-dir`；降级使用菜单 14 的已有快照回滚，不能覆盖未知目录。 |
| 重跑后直接打开管理菜单 | 同版本/旧版已完成实例默认进入管理，这是预期行为。更新选 `14 → 1` 并数字确认；未完成或保留数据卸载的实例会继续恢复。 |
| 旧包或报告仍写 private | 这是 2026-09-06 公开之前的历史内容，不再是下载要求。旧 tag、包和校验值保持不变，最新操作看 [main 教程](https://github.com/statusX7/ai-support/blob/main/docs/INSTALL.md)。 |

公开求助时不要附 `.env`、完整 Hook URL、凭据、客户正文、业务知识或备份，详见 [安全说明](SECURITY.md)。

## 组件自检结果

先用 `crispai doctor --local --json` 获取本地当前结果，再根据需要运行 `--full`。默认检查不付费推理、不重启、不改变人工状态；`--full` 会发送少量合成模型请求。`2` 表示警告/待接入，可在菜单返回；只有明确关键故障才需要修对应组件。

| 结果项 | 核对与修复 |
| --- | --- |
| Docker daemon/Compose FAIL | 检查权限与本机 context；`--fix` 可补依赖/启动受支持 daemon。下游未检查不能算成功。 |
| 容器 unhealthy/restarting/OOM | 查看该组件最近脱敏日志和资源；running 不足以证明健康。`--fix` 不反复重建仍在运行的异常容器。 |
| PostgreSQL 应用认证 FAIL | 对照完整备份与数据库角色密码；端口或 pg_isready 正常不能替代 SELECT 1。不要仅生成新密码。 |
| AnythingLLM Key/工作区/Prompt FAIL | 先按 doctor 区分认证/工作区与 Prompt 偏离。原文正确但外部内容被修改，用 `16 → 6 → 2` 或 `crispai apply --force-external` 同步并回读；认证失败按完整受管配置核对，不另建第二个 workspace 掩盖偏离。 |
| n8n Code/runner FAIL | 核对目标 workflow、runner 和生产路径；普通反代 401 不算通过。修复后重新运行当前检查。 |
| adapter/协议或主备池 FAIL | `3 → 1/9/11` 分别查看池、显式测试和近期切换记录；区分非秘密原文、有效投影、秘密代次与实际 adapter 回读。不要用陈旧 `.env` 覆盖整个池。 |
| 知识上下文预算或事务 FAIL | 对照接口池预算、容器实际值与鉴权 API，不能只看 `.env`。中断事务用 `3 → 10 → 12` 成套恢复；正在执行的应用不抢占，不能手删事务标记解除保护。 |
| 知识 pending/WARN | 正常处理期先等待并对账；空库显示未配置/不适用，不会被默认自检重建或删除。 |
| worker/恢复扫描异常 | 检查独立执行证据、租约及积压；没有客户消息本身不是故障。保留会话文件并修复 n8n，不解除永久人工。 |
| Crisp 旧观察失效 | 更换凭据或 Hook 后旧成功不再证明当前接入；使用自己的测试访客重新观察。 |
| 自检超过预算 | 单项与总检查有截止时间，默认 90 秒；适当增大 `--timeout` 后重跑。报告写出未检查项而不把超时改绿。 |

`2 → 3` 是带时间的缓存，`2 → 5` 导出当前脱敏 JSON；诊断文件默认 0600，公开前仍核对不含私人路径或业务摘要。

## Provider 与 Prompt

| 现象 | 核对与修复 |
| --- | --- |
| `/models` 404、空列表 | 主接口用 `3 → 2 → 5` 手填真实模型，编辑页 `9` 验证保存；备用从 `3 → 4` 选择后编辑。不编造默认模型。 |
| `/models` 401/403 | 检查 Key 与权限，不将鉴权错误视为“不支持列表”。主接口换 Key 用 `3 → 2 → 3`，编辑页 `9` 验证保存。 |
| 更换供应商被旧模型挡住 | `3 → 2` 同时填写主接口候选地址、Key、协议和新模型，编辑页 `9` 验证整组；未确认前有效池保持不变。 |
| 429 或请求超时 | 列表请求有限重试后显示独立的可重试错误：数字 1 重试、2 返回修改、0 取消；不伪装成“没有模型”或直接手填成功。检查配额/限流与网络，不循环扫描所有模型。 |
| 宿主可用但容器失败 | 用 `3 → 9` 选择该接口测试实际 adapter 请求；宿主 loopback 在容器里不是同一主机，受管地址会映射 host gateway。若 Provider 只监听宿主回环，需让它接受受控 Docker 网关访问。 |
| URL 前缀不对 | 输入供应商给定 Base URL，保留 `/proxy/v1` 等前缀；不要自行加第二个 `/v1`。 |
| Responses 探测成功但聊天失败 | 主接口协议在 `3 → 2 → 6` 核对，实际测试用 `3 → 9`；adapter 应按选中接口协议转换。查看健康、能力与近期记录，不只凭 HTTP 200 通过。 |
| 自定义 Header 不生效 | 主接口在 `3 → 2 → 7` 设置，备用先从 `3 → 4` 选择；编辑页 `9` 保存。拒绝换行和受管认证/协议头；值隐藏且不随业务导出，迁移后必要时重新填。 |
| 新 Prompt 看起来没用 | `4 → 1` 看受管正文/应用代次，`4 → 7` 用合成问题验证；同一会话下一问应使用新正文。直接编辑后用普通 apply；原文没变而 Web UI 偏离时用 `16 → 6 → 2` 或 `crispai apply --force-external`，普通 apply 的无变更快速路径不会修复外部偏离。 |
| 图片无法理解 | `3 → 9` 选择接口后显式测试图片；无图片能力或上下文不足的备用不会接收本次图像调用。图片过期、超限、不安全 URL 或全池无法处理时提示补文字，不自动转人工。 |
| 图片回复却重复了上一道文字题 | v1.2.1 已将识图改为独立提取当前图片事实，历史只作引用背景。先核对正在运行的版本和工作流，再用自用会话的新图片及后续指代验证；不要只看非空响应，也不要删除用户历史或修改业务 Prompt 来遮住错误。 |
| Prompt 已保存，但完整性检查拒绝推理 | workspace 保存全文不证明 AnythingLLM 没在生成前截断。核对 `3 → 2/4 → 8` 的真实上下文能力，以及聚合窗口应用结果。缩减非必要 Prompt 或依服务商资料/受控测试设置合理窗口；不要删正文护栏、仅提高数字或盲试所有接口。 |
| 主接口失败却未用备用 | `3 → 1/11` 核对是否真有启用备用、能力/上下文足够且未在冷却。零备用合法但不能容错；停用和缺 Key 草稿不能用于回答。 |
| 切到另一模型仍有额度错误 | 同源、同 Key/请求头的多个模型不等于独立账号。认证和额度失败按共享凭据范围冷却，不能通过改模型名绕过。 |
| 全池失败、保护中或预算耗尽 | 一个问题默认共用 90 秒/21 次，图片两阶段共享；到期即终止，不自动反复重发。检查近期错误类别和实际余额/网络；不要删除预算状态或清人工来继续旧问题。 |
| 上游要求很长时间后再试 | 尊重 `Retry-After`，即使超过默认 300 秒冷却也不截短。没有后台付费轮询，等待允许时的新问题或管理员明确测试。 |
| 安全拒绝没有转到备用 | 预期保护。安全拒绝、内容过滤和明确输入错误是终态，不换服务绕过；正确处理问题内容，不把它当网络故障修复。 |
| 超过主备容量或无法停用主接口 | 池最多 21 项，含停用/草稿；先确认删除无用备用。全池必须保留一个启用主接口，需要替换时使用 `3 → 7` 原子设主。 |
| 修改 `.env` 后接口没变 | 已迁移实例以 `provider-pool.yaml` 和有效投影为准，旧 `AI_*` 只是兼容投影。从菜单 3 编辑，或校验后显式 apply 池源，不能多处同时写。 |

## Crisp、按钮和人工状态

| 现象 | 核对与修复 |
| --- | --- |
| REST 401/403 | `10 → 2/3/4/9` 核对 Website ID、Identifier、Key、tier；详见 [CRISP](CRISP.md)。API Key、URL Secret 和 Plugin Signing Secret 不能混用。 |
| 本地正常、公网 Hook 不通 | 检查 DNS A/AAAA、有效证书、80/443、反代实际 upstream 端口；不要停止其他网站。`10 → 7` 私密显示准确 URL，不能用 `/webhook-test/`。 |
| 生产路径 404 | 先看菜单 2 的 n8n 生产 Code 与公网两层结果。v1.1.1 受管 Caddy 旧模板的兜底 respond 可能抢先返回 404；v1.2.0 用互斥 handle 修复，升级只替换已知旧受管模板，定制站点不覆盖。workflow 未激活时从 `1 → 1` 保留配置继续应用初始化；不要用 `16 → 6` 的资料应用冒充发布工作流。 |
| Hook 已接收但回消息 `400 invalid_data` | v1.2.0 实机复现过旧版出站自定义 properties 被 Crisp 拒绝；这些键已移除，新版只用官方消息字段并登记本地自有 fingerprint。菜单 14 升级后用新隔离访客问话验证，不重放所有失败任务。HTTP 400 不能一律归因于 Token 或 Cloudflare。 |
| Website 模式已有 Hook，doctor 仍报旧绑定 | v1.2.0 将未使用的 Hook Secret 空值按 Compose 的哨兵默认值统一比较。真实修改当前 Key/Hook 仍会使旧观察失效；修复不是把历史记录无条件设为 ready。 |
| “人工”没有按钮 | `6 → 1/4/7` 检查规则启停、排除词、优先级、冷却；全局关闭或会话已人工时不会自动展示。不要改成关键词直接暂停。 |
| 有按钮，点击不暂停 | 先检查后台订阅 `message:updated`。回调可能没有 from/type；按钮过期、配置/会话代次变化、跨会话或已消费会拒绝。用新合成会话再展示/点击。 |
| 输入按钮文字没有转人工 | 正常安全行为：必须点击本会话已登记的合法 picker，不接受伪造 choice 或普通文本。 |
| AI 回复后自己被暂停 | 核对 `message:received` 的本机自有 fingerprint/持久索引及历史 automated，必要 REST 回查是否被 403 拒绝；不要删除身份索引或通过昵称、相同正文猜机器人。 |
| 真人回复未暂停 | 需要 `message:received` 公开回复；note/在线/已读/打开后台不是公开回复。看 `7 → 3`；v1.2.1 同时识别官方缺省 automated 的操作者 ID 结构，并优先处理已确认真人，不让普通队列容量挡住暂停。不要求额外手写 Header。网站级 REST 测试不等于后台真人操作，不能只以请求带 false 判断。 |
| A 人工影响 B | 属核心异常，不是正常设置；先用总开关暂停自动出站并保留诊断，确认网站+session 隔离、当前配置代次，勿清空所有状态掩盖问题。 |
| 倒计时不恢复 | `7 → 1/3` 看 0 永久人工与最后真人时间；用户消息不延长。正数结合 5 秒扫描及消息到达检查，到期只回答新消息。全局关闭仍静默。 |
| 修改默认秒数没改变当前会话 | 默认只影响未来接管/真人新回复；要改已暂停会话用 `7 → 5` 数字选择，或 `7 → 4` 明确恢复。 |
| 旧人工会话列表不全 | v1.0.1 旧文件只有 session 哈希；首次该会话再来事件时迁移并保留状态，无法由哈希反推名称。不要删除旧状态。 |
| 慢模型答案在人工作用后出现 | 看真人控制是否已到达且确认；本机确认后未发出的旧代次会丢弃，已被 Crisp 接收的在途 POST 无法追溯撤回。 |
| 发送超时/重试重复 | 先保留发送记录并对账 fingerprint，不手动反复重放。跨系统不承诺严格 exactly-once。 |

## 欢迎与菜单

`9 → 2/3` 只控制欢迎；`8` 才是总开关。欢迎开启也不会给已欢迎过或人工模式的会话重复发送。页面加载/打开模式需 `9 → 9` 生成的无密钥 SDK、两个公开 GET 路由和 `session:sync:events` Hook。`session:set_opened` 是 operator 行为，不能替代网页事件。

旧版“关闭欢迎”成功后曾回显 runtime 的 `enabled:true`，这是总开关，不是欢迎。用 `9 → 1` 查看欢迎实际状态，并通过资料状态/doctor 核对源与有效投影；v1.2.1 普通菜单会按欢迎对象显示中文结果。不要为消除这个回显关闭全局客服、重建容器或清欢迎去重状态。

自动展开独立于欢迎文字：确认 `9 → 6`、CSP 和 SDK 配置请求；配置不可取、总开关关或人工时不强开。多个标签页/刷新不应重复欢迎。菜单引用失败、删除被引用节点或环被拒绝时，先在 `9 → 8` 修父子关系/返回按钮，再应用，不直接改运行时 JSON 绕过校验。

## 评价邀请与历史统计

v1.2.1 不再由程序追加评价文案、评分链接或按钮。升级、重复初始化和旧业务导入都停用邀请；旧待评价状态不消费“是/否/👍/👎”，历史记录仍可从菜单 11 查看。不要通过清统计、人工 offer 或普通待处理任务实现禁用。

如果新版仍出现类似邀请，先确认最终程序/生产工作流版本，再区分用户 Prompt、欢迎/规则正文、其他 Crisp 自动化与本项目自动追加；模型自己写出的文字不能凭外观判定为旧评分流程。保留脱敏步骤，不公开 Prompt/客户正文。菜单 11 没有“重新启用自动评价”入口是预期行为。

若名称旁仍显示 Bot/机器人，分别核对实际发送者昵称、正文和 SDK 独立徽标。本项目采用中性“在线客服”且不请求可选 automated 标记，但平台显示必须实测；不要删除持久自有指纹索引、伪造真人字段或注入网页 CSS 来凑结果。旧历史消息的既有标签不等于新版仍添加标签。

## 更新、迁移和卸载

业务迁移包不含秘密但含知识正文；完整本机备份包含 `.env`、数据库及会话，是敏感副本。两者不能互相冒充。校验失败、超限或损坏 schema 不导入；应用失败先检查恢复状态，旧凭据不被空模板覆盖。

接口池按稳定 ID 对应本机秘密：导入主接口没有本机 Key 时，只保存无秘密草稿，当前池继续服务；缺 Key 的新备用只能停用待补，不是已经接通。不要为“完成导入”删除当前主接口或复制 Key 冒充独立服务。补齐、验证与显式应用步骤见 [接口池迁移](CONFIG.md)。

从 v1.0.1 升级使用完整新版目录与目标版本工具，失败看自动回滚结果。AnythingLLM 数据目录交换后需要重建绑定该目录的容器，项目回滚器已处理；不要只 restart 掩盖旧 inode。镜像缺失或磁盘不足先恢复条件，勿删除快照换取假成功。

完整恢复先校验归档、历史镜像和备份内数据库密码；这些检查失败时不会拿无效凭据覆盖部署。若已进入文件/数据库变更后失败，脚本会保持 n8n、AnythingLLM 和适用的协议适配器停止，记录失败状态，并显示保留的恢复材料、变更前目录及安全快照。**此时不要从服务菜单强行启动，也不要只换回一个 AnythingLLM 目录**：数据库可能已部分恢复，单边启动会混用不同代际的数据和凭据。

先按实际错误修复磁盘、历史镜像或数据库连接条件，再使用同一份可信完整快照成套恢复 `.env`、数据库、AnythingLLM/n8n、知识和人工状态。脚本会同步 PostgreSQL 角色密码；只编辑 `POSTGRES_PASSWORD` 不会改变已有数据库角色。保留安全快照，不把密码或完整恢复包贴到公开日志。

入口可用时选择 `13 → 3`；入口不可用但受管程序完整时：

```bash
sudo bash /opt/crisp-ai/scripts/restore.sh --deploy-dir /opt/crisp-ai --full --input /绝对路径/完整备份.tar.gz
```

自定义部署目录替换路径。若应用已不一致且不能再创建安全备份，优先按失败页给出的确切安全快照命令恢复；只在确认完整安全副本存在后使用其跳过重复安全备份参数，不把该参数设为日常默认。完整清理后先从正式包在同路径安装，再按[高级维护](ADVANCED.md)成套恢复；业务迁移包不能代替数据库灾难恢复材料。实际恢复测试范围见对应发布报告，不能省略日常备份校验。

安全卸载后 `crispai` 被移除是预期行为；从完整包同路径重装重建入口并复用数据。完整清理前核对删除路径与外部备份；备份失败或非本项目容器占网时停止，不得全局 prune、卸载 Docker 或删外部容器。`0` 取消、EOF 和非法输入不会同意清理。

## 用户资料与日志维护

`16 → 8` 显示实际资料路径、未应用变化与投影状态。直接编辑现有 Prompt/知识条目后用 `crispai apply --check`，再 `crispai apply`；新增知识文件用菜单 5 导入登记，而不是手工改 manifest。中文、空格和 Emoji 文件名按正常路径引用，来源及父目录不允许符号链接。空目录须明确跳过，不能将零个可导入文件声称索引完成。

| 现象 | 核对与修复 |
| --- | --- |
| 空 Prompt、损坏 UTF-8/JSON/YAML 或越界 | 按具体校验提示改原文；未通过不会替换上一份生效投影。数字是 UTF-8 字节，不是汉字数量；见 [限制表](CONFIG.md)。 |
| 资料 `applying` 或映射代次不一致 | 先修实际 Prompt/索引/组件失败，再重新应用；回退未确认时保持停发保护，不手改 projection 为 applied，不清人工状态。 |
| 资料应用时按 Ctrl+C 或收到停止信号 | 中断不是应用成功。v1.2.1 保留 130/143 退出码及候选原文，无法确认外部状态时继续停发；检查组件后重跑 `crispai apply` 完成同步和回读，不手工解除 `applying`。 |
| apply 提示业务成功、接口池失败 | 是部分完成，不是全部回滚或全部成功。业务新值保留，池沿上一有效值；从菜单 3 查候选认证/能力或 adapter 回读，修复后再明确应用，不覆盖业务原文。 |
| 自检提示日志策略未应用 | `15 → 1/6` 比较期望与实际容器轮转。应用需重建本项目容器，先阅读停机提示；配置文件改了不代表已有容器生效。 |
| 日志清理 timer 不运行/缺归属 | `15 → 1` 查看系统级单元和上次时间。安装/升级负责登记；不要放进临时账号 cron，不能删除未知单元。受管安装续跑可重建正确归属。 |
| 磁盘占用仍高 | 区分容器日志、业务数据库/索引、完整备份与普通日志。`15 → 5/7` 只清受管过期日志，不删 WAL/索引/任务，不直接 truncate Docker LogPath 或全局 prune。 |
| 持续日志查看停不下来 | Ctrl+C 应只回菜单，不停止服务；若连接本身断开，重新登录查看服务与退出结果，不能认为清理已经完成。 |
| 日志提示无法完整读取秘密清单 | 先核对受限 `.env` 和主备秘密代次的文件类型、结构及权限。过滤器会拒绝链接、损坏或超量清单；保留原件并修复来源，不删除历史/草稿秘密或绕过脱敏继续导出。 |
| “诊断包二次秘密扫描未通过” | 未生成归档，不代表已泄漏。v1.2.1 修复了把已知模型 token 数量误作密钥的分类问题；仍出现时保留本机证据，从菜单 15 检查来源，不关闭扫描或把原始日志贴到公共 Issue。 |

日志入口 `15 → 2/3` 有界查看，`15 → 4/5/7` 先预览后数字确认清理，`15 → 8` 导出脱敏诊断包。仍不要公开用户消息、截图、业务知识或备份，也不要运行 `set -x`、`source .env` 或输出完整 `docker compose config`。
