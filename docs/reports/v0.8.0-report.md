## 5. 修改内容与新增功能

- 安装流程改为 `installing`、`staged`、`ready` 两阶段提交，只有容器、AnythingLLM bootstrap、工作区、Prompt、workflow 和完整健康检查均通过后才写入 `ready`。
- 安装、更新、备份、恢复、快照、回滚和卸载共用非阻塞维护锁；输入边界、目录、端口、URL、环境变量和文件类型检查得到加固。
- Provider 自动检测会读取 `/v1/models`，再实际调用 `/v1/chat/completions`；可选探测 `/v1/responses` 和真实图片输入，拒绝 HTTP 200 但响应为空或包含错误的伪成功。
- AnythingLLM 首次安装支持自动登录、创建或验证 Developer API Key、创建工作区、同步 Prompt，并固定使用 `chat` 模式保持同一 Crisp conversation 的上下文。
- 知识库同步对 Markdown、TXT、PDF、DOCX 执行上传、索引状态复核、旧索引回退、源文档删除及失败垃圾清单重试，不把文件正文写入统计。
- Crisp Website Hook 与 Plugin Hook 使用独立 Secret；Plugin 校验原始请求体、时间戳和 HMAC，Website 校验随机 URL Secret，二者不相互降级。
- 修正 Crisp 事件方向：访客使用 `message:send`，公开且非自动的 operator 文字或文件使用 `message:received`；operator 任意回复内容都会关闭 AI。
- 用户转人工仅按 `config/handoff.yaml` 的精确关键词或明确菜单动作触发，发送配置提示、关闭 AI 并添加配置化 `human_required` 标签。知识未命中、低置信度和 Provider 失败只安全回复及标记。
- AI 开关、接管代次、欢迎、菜单和重复 fingerprint 写入受限持久化控制文件，使用并发锁和原子替换，并按 7 天、2000/1500 条阈值清理。
- 发送 AI 回复前再次读取 Crisp 消息并复核人工接管代次；普通回复在复核失败时安全取消，显式转人工提示不被自身关闭状态阻断。
- Conversation 标签先读取已有 `segments` 再做去重并集合并；读取或写入权限不足时跳过标签，不影响正文回复。
- 匿名问题、AI 回复、知识命中、未命中、转人工、发送失败和反馈事件支持受限文件及五级轮转；管理脚本可查看命中率、好评率和高频失败问题。
- 版本快照升级为包含 n8n PostgreSQL 逻辑备份、AnythingLLM 数据、程序配置和本机镜像 ID 的一致性格式；增加容量预检、历史保留和缺失镜像的修改前失败保护。
- 迁移备份不含 `.env`；恢复校验完整文件集合、SHA-256、重复路径、路径穿越、链接、特殊文件和 Provider 敏感字段。
- 增加本地真实部署检查、显式启用的外部 E2E、归档攻击测试、Git 历史密钥扫描、n8n Code node 行为测试和严格 `v1.0.0` 发布门禁。
- 新增 `docs/RELEASE.md`；安装文档明确 Crisp Plugin Token 至少需要 `website:conversation:messages` 与 `website:conversation:sessions` 的 read、write 权限。

## 9. 风险说明

- 独立 Compose 解析不能证明 Docker daemon、容器入口、固定镜像架构或 n8n/AnythingLLM 运行时 API 兼容。
- n8n workflow 采用先响应 Webhook、后继续处理的模式；进程在确认接收后崩溃时可能丢失该次处理，当前去重策略优先防止重复回复而不是提供严格的至少一次投递。
- Crisp 标签使用读取后合并再写入；极端并发下仍可能存在 REST 读改写竞态，需在真实环境观察。
- 发送前复核可显著缩小人工与 AI 竞态窗口，但无法消除复核完成到 Crisp 接收 POST 之间的最后时隙。
- 自动脱敏覆盖常见 Token、JWT、邮箱和号码格式，不能保证识别所有自由文本个人信息；生产方仍应限制统计文件访问和保留期限。
- 回滚依赖快照中的本机镜像 ID；镜像被外部清理后会在修改前安全中止，但必须重新取得对应历史镜像才能继续。
- 回滚过程中若数据库已经恢复而后续健康检查失败，需要使用自动创建的回滚前安全快照进行人工恢复；真实故障演练尚未验证该恢复手册。
- 镜像固定到版本 tag 而不是 digest；正式验收应记录实际 digest，并评估供应链固定策略。
