# v1.3.3 OhMyGPT 兼容性修复报告

## 已确认根因

在重装后的 TARGET-A 上，v1.3.2 正常管理入口可取得 OhMyGPT 的 247 个模型，但 `gpt-5.6-sol` 保存前探测失败。上游返回 HTTP 400，明确指出 `max_tokens` 不受支持，应使用 `max_completion_tokens`；更换字段后，上游又明确拒绝温度 0.7。原适配器只能处理后一种参数差异，不能完成前一种调整。管理层还将 `invalid_request` 改为 `protocol_error`，误导用户反复修改地址。

同一密钥下 Claude 和 DeepSeek 的直接短请求返回正常。这只能限定原问题的复现范围，不替代项目的完整问答验收。未将用户此前的失败归咎于服务商。

## 修改范围

适配器仅识别明确的参数拒绝和替代建议，在同一候选上保持输出额度并使用剩余时间重试；最多分别调整一次输出字段和温度。兼容缓存沿用有界内存及一小时有效期，按候选配置与认证身份隔离，不修改客户输入或供应商模型 ID。

管理菜单、配置查询、doctor 和 n8n 保留参数错误分类。不能处理的真实输入错误仍终止，不盲目遍历全池，也不把发送固定文案记为模型成功。没有删除功能、知识资料、凭据或历史任务；原图片验证、人工保护、主备策略和出站去重不变。

## 验证范围

修复和受影响回归均在 TARGET-A 执行，外部协议故障使用隔离合成上游。适配器覆盖连续参数拒绝、额度保真、凭据隔离、共享超时及不应重试的反例；运行时核对同候选三次有界请求只产生一条业务发送，以及真正参数错误保持未完成责任。主备协议、菜单和静态检查复用已通过部分，再继续剩余用例。

旧接口池夹具把普通文字当作合法图片探测返回，导致编辑及导入测试失败；已改为仅对精确内置图片和问题返回正确颜色，未放宽产品校验。失败记录保留，测试用例恢复执行不计为新增业务缺陷。

正式发布前必须将冻结完整包安装到 TARGET-A，并用真实 OhMyGPT 账户通过 GPT、Claude、DeepSeek 的完整知识问答及一条 Crisp 精确送达；结果、归档摘要和运行边界记录在同一 Release 的核验附件。安装和 Caddy 逻辑未改，复用 v1.3.2 已完成的空机和失败续装证据，不据此声称本轮重跑了全项目。

## 参考

[OhMyGPT Quickstart](https://docs.ohmygpt.com/docs/quickstart)给出 `/v1` 基址与 Bearer 认证；[参数文档](https://docs.ohmygpt.com/docs/api/parameters)说明模型参数会传递至底层供应商。具体兼容条件依据 TARGET-A 的实际 HTTP 400 结构，而不是猜测模型名称或更换地址。开发遵循 [Stop That Shit](https://github.com/lennney/stop-that-shit)：只修实际责任链，复用有效验证，不引入新框架。
